Java 基础语法

001基础

什么是 JDK、JRE 与 JVM？它们之间有什么关系？

JVM 是运行 Java 字节码的虚拟机，提供跨平台能力；JRE 是 Java 运行环境，包含 JVM 与核心类库；JDK 是开发工具包，包含 JRE 以及 javac 等编译调试工具。JDK > JRE > JVM，写代码需要 JDK，运行只需要 JRE。

002基础

Java 中有哪几种基本数据类型？

共 8 种：整数类型 byte、short、int、long，浮点类型 float、double，以及字符 char 和布尔 boolean。除 boolean 外均有明确字节数，如 int 占 4 字节、long 与 double 占 8 字节。

003基础

Java 的注释有哪几种？

有三种：单行注释 //、多行注释 /* */ 和文档注释 /** */。文档注释可通过 javadoc 工具生成 API 文档，是声明类、方法时标注说明的常用方式，编译器会忽略注释内容。

004基础

Java 中 == 和 equals 有什么区别？

== 比较两个变量的值：对基本数据类型比较数值是否相等；对引用类型比较是否指向同一个对象（即比较引用地址）。equals 是 Object 的方法，默认等同 ==，需要类重写才能按业务内容比较，如 String 重写了 equals。

005基础

String 是什么类型？为什么它常用？

String 是引用数据类型，不是基本类型，可参与字符串拼接和内容比较。String 常用因为它是被 final 修饰的不可变（immutable）类，线程安全且可被字符串常量池复用，适合作为常量与键值。

006基础

数组有哪些声明和初始化方式？

声明如 int[] a; 或 int a[];；初始化可 new int[5] 或用大括号直接赋值 int[] b = {1,2,3};。数组长度用 length 属性获取，下标从 0 开始，越界会抛 ArrayIndexOutOfBoundsException。

007基础

static 关键字有哪些作用？

static 让成员属于类而不是对象：static 变量与方法由类名直接访问，无需 new 对象；static 代码块在类加载时执行一次，用于类级初始化。static 方法不能直接访问非 static 成员，因为可能没有实例。

008基础

Java 有哪几种访问修饰符？

四种：public（任意可访问）、protected（同包及子类）、默认包级（同包可访问）、private（仅本类）。访问范围从小到大依次为 private、默认、protected、public，常用于封装数据控制可见性。

009基础

什么是方法重载（overload）？

方法重载指在同一个类中方法名相同但参数列表不同（个数、类型或顺序不同）。它与返回值类型无关，编译期根据实参决定调用哪个版本。重载是实现多态的一种编译期形式。

010基础

this 关键字的作用是什么？

this 指向当前对象，可用来区分同名成员变量与局部变量，调用本类其他构造方法（this(...)）或成员方法。在构造方法中 this(...) 必须是第一条语句，常用于消除命名歧义。

011基础

try-catch-finally 的执行流程是怎样的？

try 块出现异常时，异常会被匹配的 catch 捕获处理；无论是否捕获，finally 块都会执行，常用于释放资源。只有执行 System.exit() 或 JVM 崩溃才会导致 finally 不执行。

012基础

throws 与 throw 有什么区别？

throw 是语句，主动抛出一个异常对象，如 throw new IllegalStateException()；throws 在方法声明上声明该方法可能抛出的异常类型，交由调用方处理。前者是动作，后者是声明。

013基础

break 和 continue 在循环中的作用是什么？

break 立即终止整个循环，跳出循环体；continue 跳过本次循环剩余代码进入下一次迭代。两者都可用在 for、while、do-while 中，配合标签可跳出多层嵌套循环。

014基础

什么是三元运算符？

三元运算符即 ?:，形如 条件? 表达式1:表达式2，条件为 true 取表达式1，否则取表达式2。它可以作为表达式赋值，常用于替代简单的 if-else，例如 int max = a>b?a:b。

015基础

基本数据类型的默认值是什么？

成员变量会获得默认值：boolean 为 false，char 为 '\u0000'，整型为 0，浮点为 0.0，引用类型默认为 null。但局部变量没有默认值，必须先显式赋值才能使用。

016基础

什么是强制类型转换？

强制类型转换在高精度类型向低精度赋值的场景使用，格式为 (目标类型)变量，例如 int i=(int)3.9。它可能丢失精度或发生数值溢出，因此需先确认取值落在目标类型的有效范围内。

017基础

逻辑与 &&、|| 具有什么特性？

&& 与 || 具有短路特性：对于 &&，左操作数为 false 就不再计算右边；对于 ||，左操作数为 true 就不再计算右边。这既提升效率，也可利用它规避空指针，如 x!=null && x.length()>0。

018基础

什么是变量作用域？

作用域决定变量可访问的范围，按从内到外分为局部作用域与类作用域。局部变量在方法或语句块内有效，超出后不可访问；成员变量在整个类实例或类的生命周期内有效。

019基础

String 如何实现字符串拼接？

最简单用 + 操作符，编译期可能优化为 StringBuilder 的 append；也可直接使用 StringBuilder 的 append 再 toString。需要频繁拼接时优先用 StringBuilder，避免产生大量中间 String 对象。

020基础

什么是可变参数（varargs）？

可变参数用 类型... 声明，如 void f(String... args)，可接收零个或多个实参，本质上是数组。它必须作为方法参数列表的最后一项，且同一方法只能有一个可变参数。

021基础

为什么需要包装类（Wrapper Class）？

基本类型不能作为对象使用，无法放进泛型容器或用 null 表示。包装类如 Integer、Boolean 把基本类型封装为对象，提供 parseInt、compareTo 等工具方法，并支持自动装箱拆箱。

022基础

++i 和 i++ 有什么区别？

两者都会使 i 自增 1，区别在返回结果：i++ 先返回原值再自增，++i 先自增再返回新值。单独作为语句时无差异，但在表达式或赋值场景中行为不同，需注意使用顺序。

023基础

整型溢出会发生什么？

整型溢出时不会抛异常，而是发生二进制环绕（wrap around），结果按位截断。例如 int 最大值加 1 变成最小值。因此大数运算应改用 long 或使用 Math.addExact 等带溢出检测的方法。

024基础

char 类型能存储什么？

char 是 16 位无符号 Unicode 字符类型，可存储单个中文字符或字符常量如 'a'。本质上是 0~65535 的整数，可作为数字参与运算。BMP 内的单个汉字就占一个 char。

025基础

main 方法的签名是什么？为什么这样定义？

标准签名是 public static void main(String[] args)。public 让 JVM 可访问，static 使无需实例即可调用，void 表示无返回值，args 接收命令行参数。JVM 依赖该固定签名定位程序入口。

026基础

什么是 package 与 import？

package 声明类所在包名，用于组织类并划分命名空间、避免类名冲突；import 导入其他包中的类，使代码中可直接使用短类名。不加 import 时也可写完整限定名。

027基础

final 修饰变量有什么含义？

final 修饰变量表示常量，一旦赋值不可再改变。局部变量可先声明后赋值再 final，实例变量则必须在声明时或构造方法中赋初值。它既可修饰基本类型也可修饰引用类型。

028基础

为什么基本类型之外还有引用类型？

引用类型通过引用（地址）指向 heap 中的对象，如数组、String、类与接口。它们没有固定字节数、默认值多为 null，支持继承与多态，与基本类型在存储与传参上的行为不同。

029进阶

String 为什么是不可变的？

String 用 private final char[] value 保存字符且不对外暴露修改方法，因此不可变。好处是 hashCode 可安全缓存、线程安全、可安全用于常量池与集合键，这也是 String 能进入字符串常量池的前提。

030进阶

StringBuilder 与 StringBuffer 有什么区别？

两者都用于可变字符串拼接。StringBuffer 的方法用 synchronized 修饰，线程安全但性能略低；StringBuilder 非同步，单线程下性能更高。现代单线程场景优先选择 StringBuilder。

031进阶

重写 equals 时为什么必须重写 hashCode？

两者约定：相等的对象 hashCode 必须相等。若只重写 equals，哈希容器如 HashMap 可能把逻辑相等的对象放入不同桶，导致查找失败。重写时要用相同的关键字段保证一致性。

032进阶

什么是装箱与拆箱（boxing / unboxing）？

自动装箱是编译器把基本类型包装成对应包装类对象，如 Integer i=100；拆箱是把包装类型转回基本类型。它们由编译器插入 valueOf 与 intValue 等调用，频繁发生会带来性能开销。

033进阶

Integer 的缓存范围是多大？

Integer 的 valueOf 会缓存 -128 到 127 的常量池对象，此范围内赋值复用同一对象，== 为 true；超出范围会 new 新对象，== 为 false。因此判断相等应使用 equals 或 intValue。

034进阶

字符串常量池存放什么内容？

字符串常量池存放 String 字面量及 intern 的对象。编译期字面量如 "abc" 会被复用，同内容的 new String 或拼接结果不一定入池。其底层实现（如版本、驻留方式）各版本存在差异。

035进阶

方法重写（override）有哪些规则？

重写要求方法签名相同、返回值可协变、访问修饰符不能比父类更严格、不能抛出比父类方法更宽的 checked 异常。重写实现运行时多态，实际调用由对象运行时类型决定。

036进阶

如何正确重写 equals？

应依次做到：先自反性判断（== 本对象返回 true）、再 instanceof 检查类型，转型后逐字段比较。基本类型用 ==，引用类型用 Objects.equals。同时重写 hashCode，保证对称性、传递性与一致性。

037进阶

foreach（增强 for）的原理是什么？

foreach 是语法糖。对数组编译为基于下标的普通 for；对集合编译为调用 iterator() 得到 Iterator，用 hasNext()/next() 遍历。因此遍历集合时不能直接修改结构，否则抛 ConcurrentModificationException。

038进阶

static 与实例成员的关键区别是什么？

static 成员属于类，随类加载初始化一份，被所有实例共享，可用类名直接访问；实例成员随对象产生，每个实例独立持有。static 方法只能直接访问 static 成员，因为可能没有当前实例。

039进阶

final 修饰方法和类有什么效果？

final 方法不可被重写，可防止子类改变行为；final 类不可被继承，如 String、Integer。两者用于固化设计，也便于编译器做安全的去虚拟化内联等优化。

040进阶

什么是递归？递归有哪些关键点？

递归是方法直接或间接调用自身来分解问题。关键要有递归出口（终止条件）与递推公式，否则会无限递归导致 StackOverflowError。递归语义简洁但空间开销大，常用循环或动态规划替代。

041进阶

try-finally 中 return 的执行顺序如何？

return 会先计算返回值并暂存，然后执行 finally，最后返回。若 finally 中又 return，会覆盖 try 中的返回值。因此应避免在 finally 中写 return，以免产生难以排查的结果覆盖问题。

042进阶

Java 方法传参是传值还是传引用？

Java 一律是值传递（pass-by-value）。基本类型传的是值的拷贝；引用类型传的是引用地址的拷贝。方法内修改对象的字段对调用方可感知，但给参数变量重新赋值不会影响外部引用。

043进阶

数组有哪些复制方式？

可用 System.arraycopy、Arrays.copyOf/copyOfRange 或循环赋值。System.arraycopy 是 native 底层拷贝较快；Arrays.copyOf 会创建新数组并返回。拷贝引用类型时是浅拷贝，元素对象共享。

044进阶

switch 支持哪些数据类型？与 if-else 如何取舍？

switch 支持 int 及可提升为 int 的 byte/short/char、枚举，以及 JDK 7+ 的 String。分支较多且依据单个值判断时 switch 更清晰；条件复杂或有区间判断时用 if-else 更灵活。

045进阶

字符串 + 号拼接的底层是怎样的？

纯常量拼接在编译期直接折叠成字面量；含变量的拼接，编译器会优化为 new StringBuilder().append(...).toString()。为了减少对象创建，高频拼接场景显式使用 StringBuilder 更可控。

046进阶

Integer 使用 == 比较有哪些易错点？

两个都处于 -128~127 缓存区间时 == 为 true；在区间外或一边是 int 一边是 Integer 时会受自动拆箱影响。安全做法是统一取出 intValue 比较或用 equals，避免依赖缓存行为。

047进阶

成员变量与局部变量的初始化有何不同？

成员变量由 JVM 自动赋默认值：数值 0、boolean false、char '\u0000'、引用 null；局部变量不自动初始化，直接使用会编译报错，必须显式赋值后才能参与运算。

048进阶

Java 异常体系是怎样的？

Throwable 分为 Error 与 Exception：Error 如 OutOfMemoryError，表示严重且通常不可恢复的问题；Exception 又分受检异常（checked，须 throw 声明或 try-catch 处理）与运行时异常 RuntimeException（unchecked，可不强制处理）。编译期对受检异常强制要求处理。

049进阶

变量存储在 stack 还是 heap？

方法内的局部变量、基本类型值与对象引用多存在 JVM 的 stack（栈帧局部变量表）；new 出来的对象实例存在 heap 中；字符串常量等位于常量池。引用指针指向堆中实际对象。

050进阶

局部变量为什么要求是 final 才能被匿名内部类访问？

匿名内部类以副本形式捕获局部变量，要求该变量不可再被修改以保证内外部一致（effective final）。Java 8 起只要局部变量事后不再被赋值，即可被捕获而无需显式写 final。

051进阶

String 常量池中的对象能否被回收？

可以。字符串常量池里的对象也由 GC 统一管理，不再常驻永存。当没有引用指向时，这些字符串对象会被垃圾回收，常量池并非 GC 免疫区域，仍遵循可达性分析算法。

052进阶

为什么 finalize() 方法不被推荐使用？

finalize() 在对象被 GC 回收前调用，但执行时机不确定、可能根本不执行，且会拖慢整个 GC，Java 9 起已标记为 deprecated。推荐改用 AutoCloseable 与 try-with-resources 做确定性的资源清理。

053进阶

如何正确比较两个浮点数是否相等？

由于二进制表示存在精度误差，直接用 == 比较两个 float 或 double 常不可靠。应比较两者之差的绝对值是否小于某个很小的阈值 epsilon，需要精确十进制时改用 BigDecimal。

054深挖

字符串 intern() 的机制是什么？

intern() 会在字符串常量池中查找内容相同的引用：存在则返回池中引用，否则把该字符串加入池中并返回。new String 经 intern 后可与其他字面量共享内容，常用于降低重复字符串的内存占用。JDK 7+ 常量池在 heap 中。

055深挖

Integer 缓存陷阱的边界细节是什么？

Integer.valueOf 对 -128~127 返回缓存对象，误用 == 会踩坑；而 int 与 Integer 混合比较时会自动拆箱，逻辑等价不等于引用相同。拆箱遇到 null 会抛 NullPointerException，这也是高频易错点。

056深挖

什么是浅拷贝与深拷贝？

浅拷贝只复制对象的引用，字段指向的对象与新对象共享；深拷贝会把字段指向的对象也复制一份。数组的 clone 与拷贝默认是浅拷贝。深拷贝可通过序列化或手动逐层 new 实现。

057深挖

finally 中出现异常或 return 如何影响原异常？

若 finally 抛出新异常或执行 return，会覆盖 try/catch 中的原始异常或返回值，使原始异常被吞掉。排查时可用 try-with-resources（抑制异常 suppressed）来保留原因，因此应避免在其中做有返回或抛异常的清理。

058深挖

递归过深为什么会导致 StackOverflowError？

每次递归调用都会在 JVM 的 stack 上新建一个栈帧，栈空间有限。当调用层数超过栈最大深度时抛出 StackOverflowError。可通过增大栈空间、改写循环或采用动态规划来规避。

059深挖

i = i++ 执行后 i 的值是多少？为什么？

执行后 i 保持原值。i++ 的语义是先取旧值用于当前表达式、再进行自增；紧接着的赋值 i = 会把旧值写回，覆盖自增结果。要点是副作用发生在取值之后、赋值之前，最终旧值被写回。

060深挖

可变参数与方法重载组合会产生哪些歧义？

调用 f(null) 时若同时存在 f(String...)、f(int...) 等重载，由于 null 可匹配多种类型，可能造成编译歧义或语义偏差。实际开发应避免制造这种模糊重载，调用时尽量提供明确类型。

061深挖

数组有何协变性（covariance）？

Java 数组是协变的：String[] 可视为 Object[] 的子类型整体赋值。但数组元素做运行时类型检查，向声明为 Object[] 的数组放入非 String 元素会抛 ArrayStoreException。泛型不协变，而数组如此设计是历史原因，用于维持类型安全。

062深挖

方法重载与重写的边界如何区分？

重载是编译期多态，同类同名、参数列表不同；重写是运行时多态，在继承体系内签名一致。static 方法是隐藏而非重写，private/final 方法不参与多态分派，需按这些边界判断行为。

063深挖

为什么说 Java 只有值传递？传递对象会怎样？

方法只拿到引用值的副本，两者指向同一堆对象，因此方法内修改对象的字段对调用方可见；但如果给参数变量重新 new 或赋值，调用方持有的引用不会改变。这与 C/C++ 的引用语义不同。

064深挖

三元表达式混合 int 与 Integer 时有哪些拆箱陷阱？

三元表达式两个分支若一个为基本类型、一个为包装类型，包装分支会被强制拆箱。若该分支值为 null，运行时会抛 NullPointerException。例如 int c = flag ? a : b 中 a 为 null 的 Integer 时即触发。

065深挖

final 引用与对象不可变的关系是什么？

final 引用只保证引用变量不能再指向其他对象，不保证对象内部状态不可变。真正不可变需要类本身不可修改其字段（如 String）。因此 final 数组或 final 集合引用仍可修改内部内容。

066深挖

静态初始化块与实例初始化块的执行顺序？

类加载时按书写顺序执行 static 代码块与静态字段初始化一次；创建对象时先执行实例初始化块，再进入构造方法。父类静态先于子类静态，父类实例初始化先于子类实例初始化，顺序固定。

067深挖

switch 的 fall-through（穿透）是什么？

fall-through 指 case 分支若无 break 会继续穿透执行后续分支语句，直到遇到 break 或 switch 结束。可用来合并多个取值，但漏写 break 是常见 bug 来源；现代 JDK 的箭头式 case 可避免穿透。

068深挖

基本类型与引用类型默认值的差异有何实际影响？

成员变量中数值默认 0、boolean 默认 false、引用默认 null；数组元素同样自动初始化。这导致难以区分基本类型变量是未赋值还是恰好为 0，而 null 更能表达缺失状态，这也是包装类在 ORM 等场景下的价值。

069深挖

Java 方法的返回值在底层如何传递？

基本类型返回值经栈帧返回；引用类型返回值返回对象在 heap 中的地址。返回数组或对象时调用方可修改其内容。方法调用信息封装在 stack 的帧中，调用结束即销毁，堆中对象生命周期由 GC 决定。

070深挖

除 Integer 外还有哪些包装类存在缓存？范围如何？

Byte、Short、Integer、Long 都缓存 -128~127；Character 缓存 0~127；Boolean 缓存 TRUE 与 FALSE；Float 与 Double 不做缓存。这些缓存由 valueOf 实现，避免了频繁创建对象，但也容易误用 == 引发表象陷阱。

071基础

什么是面向对象编程中的封装（encapsulation）？为什么需要封装？

封装指把对象的属性和行为捆绑起来，用访问控制符隐藏内部细节，外部只能通过公开方法访问。通过 private 字段加 getter/setter 实现，好处是保护数据完整性、降低耦合、便于维护，体现信息隐藏原则。

072基础

Java 中有哪些访问控制修饰符（access modifier），各自的作用范围是什么？

有四种：private 仅本类可访问；default（无修饰符）同包可访问；protected 同包或子类可访问；public 全局可访问，重写时不能缩小子类方法的可见性。

073基础

什么是继承（inheritance）？Java 支持多继承吗？

继承是子类复用父类属性和方法并扩展新功能，用 extends 实现，体现 IS-A 关系。Java 的类只支持单继承，即一个类只能有一个父类；但接口支持多继承，一个类可实现多个接口来获得多重类型能力。

074基础

什么是多态（polymorphism）？Java 中多态体现在哪些方面？

多态指同一行为在不同对象上表现出不同形态，核心是父类引用指向子类对象。体现在方法重载（编译期静态多态）和方法重写（运行期动态多态）两方面，前者靠参数列表区分，后者由继承体系中实际对象类型决定。

075基础

简述方法重载（overload）的概念，它与重写（override）有什么区别？

重载是在同一类中方法名相同但参数列表不同，与返回类型和修饰符无关，属编译期多态；重写是子类按相同签名重新实现父类方法，属运行期多态。重载解决同名不同参数，重写解决父类方法的个性化实现。

076基础

重写父类方法时有哪些必须遵守的规则？

方法名与参数列表必须一致；返回类型可相同或协变更窄；访问权限不能更低；不能抛出比父类更宽泛的受检异常；static、final、private 方法不能被重写。重写建议加 @Override 注解，让编译器协助检查信号。

077基础

构造方法在 Java 中有什么特点？它能不能被重写？

构造方法名与类名相同、没有返回值、不能被 static 或 final 修饰。它不能被重写，因为不属于继承成员；但子类可通过 super 调用父类构造器，用 this 调用本类其他构造器，都必须作为首条语句。

078基础

this 关键字的作用是什么？

this 代表当前调用该方法的对象引用，用途有三：在构造器中调用本类另一构造器 this(...)；区分实例变量与同名形参，如 this.name = name；或把当前对象作为实参传给其他方法、返回当前对象。

079基础

super 关键字的作用是什么？

super 用于访问父类成员：调用父类构造器 super(...)、访问父类字段和方法。它必须作为子类构造器的第一条语句；若缺省，编译器会隐式调用父类无参构造方法。

080基础

一个对象从创建到销毁的过程是怎样的（对象生命周期）？

对象在堆上创建，先是 new 或类加载分配内存，接着按构造链（先父后子）初始化；生命周期内被引用可达；当不再被任何根引用可达就进入不可达状态，最终被 GC 标记回收。

081基础

equals 与 == 的区别是什么？

== 比较基本类型的值或对象引用地址；equals 是 Object 方法，默认等价于 ==，但常被重写为内容比较，如 String 重写 equals 比较字符。判断引用用 ==，判断内容用 equals。

082基础

为什么重写 equals 时必须重写 hashCode？

规范要求 equals 相等时 hashCode 必须相同，否则对象在 HashMap、HashSet 中会散落到不同桶，造成重复存储或查找失败；反之 hashCode 相同不保证 equals。遵循该契约，散列集合才能正确工作。

083基础

什么是枚举（enum）？如何定义一个枚举？

枚举是一种特殊类，用于定义一组固定常量，天然具备类型安全、单例和线程安全特性。用 enum 关键字定义，如 enum Color { RED, GREEN, BLUE }；枚举常量是预创建的静态实例，可带字段、构造方法和方法。

084基础

Java 8 引入了哪几个重要的新特性？

主要有：Lambda 与函数式接口；Stream 流式 API 声明式处理集合；接口的 default 与 static 方法；新日期时间 API（LocalDateTime）；以及 Optional 处理空值。

085基础

什么是匿名内部类（anonymous inner class）？它有什么使用场景？

匿名内部类是没有名字的局部内部类，创建时就地实现某接口或继承某类，多用于一次性回调或事件监听。它可访问外部的 final/effectively final 局部变量，但无法定义构造器，适合简单临时对象。

086基础

Java 9 之后接口可以拥有哪些成员？

接口可含抽象方法、default 方法、static 方法，以及 Java 9 引入的 private/private static 方法复用私有逻辑；接口字段仅限 public static final 常量。

087基础

什么是函数式接口（functional interface）？与 Lambda 有什么关系？

函数式接口指只含一个抽象方法的接口，常以 @FunctionalInterface 标注供编译器检查。Lambda 本质是它的匿名实现，编译器把表达式绑定到该接口，二者一一对应，例如 Runnable 对应 () -> void。

088基础

Java 的 Stream 有什么作用？它和集合（Collection）有什么区别？

Stream 用于对集合做声明式流水线处理，支持中间操作（map、filter、sorted）与终端操作（forEach、collect、count）。它不是存储结构、不修改源集合，是一次性懒加载数据流，元素按需计算。

089基础

什么是反射（reflection）？Java 中如何获取一个类的 Class 对象？

反射是程序在运行期动态获取类信息并操作其成员的能力，常用于框架、注解处理和序列化。获取 Class 对象有三种方式：类型.class、对象.getClass()，以及 Class.forName("全限定名")，是运行期元编程的基础。

090基础

什么是注解（annotation）？@Override 和 @Deprecated 的含义是什么？

注解是代码的元数据。@Override 标注方法重写父类方法，让编译器校验签名；@Deprecated 标注已过时元素，编译时给出警告。注解本身不改变逻辑，需由编译器或框架通过反射读取和处理。

091基础

Java 17 的 record 关键字是做什么用的？

record 用于定义不可变的纯数据载体，编译期自动生成构造器、equals、hashCode 和 toString；字段默认 private final，整体不可变。极大简化了 POJO 的样板代码，适合作为 DTO 或值对象。

092进阶

多态的底层实现原理是什么？Java 如何决定调用哪个方法？

方法调用是分派（dispatch）的。编译期由静态类型确定可调方法集，运行期通过动态绑定（dynamic binding）获取实际对象类型；JVM 为每个类建虚方法表（vtable），按实际对象查表定位方法实现。

093进阶

抽象类（abstract class）与接口（interface）有什么区别？

抽象类可有具体方法、构造器与实例字段，体现 IS-A 层次复用；接口侧重定义能力契约，可多实现，Java 8 后支持 default/static/private 方法。要复用共享状态与构造逻辑用抽象类，定义契约用接口。

094进阶

在什么场景下应该优先选择接口而非抽象类？

当需要定义能力契约且可能被多个不相关类型实现时选接口，好处是多实现、解耦、易 mock 与测试；当多个子类需共享字段和统一的构造、模板逻辑时选抽象类。经验法则：接口定义行为，抽象类承载复用。

095进阶

接口的默认方法（default method）解决了什么问题？

默认方法让接口可在不破坏既有实现类的前提下新增方法，解决接口演进兼容性问题。实现类可继承默认实现或重写。需注意菱形冲突：当实现的两个接口提供同名默认方法时，实现类必须显式解决。

096进阶

接口中的 static 方法与 default 方法有什么区别？

static 方法属于接口本身，只能通过接口名调用，不能被子类继承或重写；default 方法属于实例，通过实现类实例调用并参与继承与重写。两者都提供代码实现，但归属和调用方式不同。

097进阶

子类创建对象时，初始化顺序是怎样的？

顺序为：先执行静态初始化（先父后子、仅一次），然后父类的实例变量初始化与初始化块、父类构造器，接着子类的实例变量初始化与初始化块、子类构造器。即先静态后实例，实例层先父后子。

098进阶

静态代码块、实例代码块和构造方法的执行顺序是如何排列的？

静态块在类加载时只执行一次且最先；实例块每次 new 时执行，位于构造器外层先运行；构造方法体最后。整体顺序：父类静态块、子类静态块，再父类实例块与构造器、子类实例块与构造器。

099进阶

构造方法能否调用可被重写的普通方法？会有什么问题？

可以调用但有风险，因为构造期间调用被子类重写的方法时子类字段尚未初始化，可能读到默认值或引发空指针。最佳实践是构造器中只调用 final、private 或静态方法，避免可被重写的方法。

100进阶

Java 内部类有哪些种类？成员内部类有什么特点？

有四种：成员内部类（依附外部实例）、静态内部类（与外部实例无关）、局部内部类（方法内定义）、匿名内部类。成员内部类可访问外部类所有成员，需通过外部类实例 new 创建，隐式持有外部引用。

101进阶

静态内部类与成员内部类有什么区别？

静态内部类用 static 修饰，不持有外部类实例引用，可独立创建，只能访问外部类静态成员；成员内部类依赖外部实例，可访问外部所有成员，须经外部实例创建，携带外部引用过长可能引发内存泄漏。

102进阶

为什么局部和匿名内部类访问外部变量要求其 final 或 effectively final？

因为内部类捕获的是外部变量的副本而非引用，为保证副本与外部值一致固定，编译器要求变量 final 或 effectively final。这是 Java 实现闭包时的语法约束，防止捕获值被随意改动造成不一致。

103进阶

Lambda 表达式的本质是什么？它与匿名内部类有何区别？

Lambda 是函数式接口的实例，编译器用 invokedynamic 生成、不产生独立 class 文件；匿名内部类每次都会新建类。Lambda 不持有外部类的 this 引用，语义更接近静态方法，因此更轻量高效。

104进阶

介绍一下 Stream 中中间操作与终端操作的区别。

中间操作返回新 Stream 且惰性执行，如 filter、map、sorted，不立即计算；终端操作触发整个流水线并产出结果，如 collect、forEach、count。没有终端操作时，Stream 链不会真正运行。

105进阶

Stream 与 parallelStream 的区别是什么？使用并行流要注意什么？

parallelStream 借助 ForkJoinPool 在多核上并行处理元素，数据量大且无依赖时可提速。但需保证结果可无状态合并、避免共享可变状态，且并行不一定更快，要权衡排序开销与线程切换成本。

106进阶

什么是泛型的泛型擦除（erasure）？它带来了什么后果？

泛型只在编译期做类型检查，运行期会擦除类型参数并替换为原始类型或边界。后果是运行期无真实泛型类型：不能 new T()、不能创建泛型数组、instanceof 不能针对具体类型参数判断，且伴随强转。

107进阶

泛型中 通配符 ? extends 与 ? super 的区别是什么？

? extends T 限制类型为 T 或其子类，可安全读取为 T，但不能写入，称上界通配符；? super T 限制为 T 或其父类，可安全写入 T，读取只能当 Object，称下界通配符。它们用于放宽泛型适用范围。

108进阶

什么是 PECS 原则？

PECS 即 Producer Extends, Consumer Super：要从集合读取元素时用 ? extends，要写入时用 ? super。它让通配符与读写方向匹配，是泛型的经典经验法则。

109进阶

反射中 getDeclaredFields 与 getFields 有什么区别？

getFields() 返回本类及父类的 public 字段；getDeclaredFields() 仅返回本类声明的所有字段（含 private），不含继承字段。访问私有字段需 setAccessible(true)。

110进阶

反射中 Method.invoke 的用法是什么？访问私有方法如何操作？

先用 getDeclaredMethod 获取 Method 对象，再调用 invoke(实例, 参数...) 执行；静态方法传 null 实例。调用私有方法需先 method.setAccessible(true) 关闭访问检查。

111进阶

什么是注解？如何自定义一个在运行期可用的注解？

注解用 @interface 声明；要在运行期反射读取，须加 @Retention(RUNTIME) 并用 @Target 指定作用位置。成员用无参方法定义并给默认值，之后经反射 getAnnotation 读取处理。

112进阶

JDK 内置注解和元注解有哪些？举例说明。

JDK 内置注解有 @Override、@Deprecated、@FunctionalInterface；元注解有 @Retention、@Target。框架注解如 Spring 的 @Component 等在运行期被反射处理。

113进阶

枚举为什么天然线程安全且单例？枚举对象的创建时机是什么？

枚举常量是编译期生成的静态实例，在类加载的初始化阶段由 JVM 保证只创建一次，受类加载机制保护所以线程安全。又因构造函数受限、反序列化返回同一实例，枚举可作为安全且唯一的单例。

114进阶

深拷贝（deep copy）与浅拷贝（shallow copy）的区别是什么？

浅拷贝只复制对象本身及其引用字段的地址，拷贝前后引用字段指向同一对象，修改互相影响；深拷贝会递归复制所有引用对象，使两者完全独立。浅拷贝由 Object.clone() 默认实现，深拷贝靠序列化或递归。

115进阶

clone() 属于哪个类？如何使用它实现对象拷贝？

clone() 是 Object 的 protected 方法，默认逐字段浅拷贝。须实现 Cloneable 并重写为 public 调用 super.clone()；否则抛 CloneNotSupportedException。

116深挖

多态调用在 JVM 层面如何实现动态绑定？结合方法分派机制说明。

编译期记录被调方法的符号引用并确定静态类型；运行期 invokevirtual 指令依据操作数栈顶实际对象类型，在类的 vtable 中定位方法入口完成动态绑定。热点方法会由 JIT 用内联缓存降低分派开销。

117深挖

简述虚方法表（vtable）的布局，以及继承入口如何复用和偏移如何确定。

每个类生成一张 vtable，槽位对应虚方法入口；子类表先复制父类表，重写方法覆盖对应槽位，父类方法偏移保持不变，新增方法追加尾部。调用时按固定偏移取入口，接口方法另有 itable 表。

118深挖

为什么方法调用优先用 vtable 分派而不是每次全表搜索？

vtable 用 O(1) 偏移查表取代方法引用搜索，并由继承树维护一致性；再叠加 JIT 内联缓存与去虚化把热点转直接调用，兼顾了正确性与性能。

119深挖

泛型擦除会导致哪些经典类型检查陷阱？请举例。

List<String> 与 List<Integer> 运行期都是 List，instanceof 无法区分；new T[] 非法；仅靠泛型参数不同不能重载，签名冲突；static 方法不能访问类级类型参数，均由 erasure 所致。

120深挖

当需要运行时保留泛型信息（如反序列化泛型）时通常怎么做？

用 TypeReference 以匿名子类携带父类泛型信息，通过 getGenericSuperclass() 与 ParameterizedType 反射还原真实类型，从而绕过 erasure。

121深挖

? extends 与 ? super 分别如何影响读写，为什么会有这种限制？

? extends T 保证类型是 T 或其子类但具体未知，不能安全写入，只能读 T；? super T 保证能容纳 T 及其子类，可写 T，但读出只能回 Object。该限制源于协变/逆变类型安全，防止类型不安全混入。

122深挖

深拷贝的序列化与反射递归两种实现各有什么利弊？

序列化深拷贝简单但要求所有对象 Serializable，性能开销大且 transient 字段丢失；反射递归更精细、可自定义处理引用图（含环），但实现复杂、需处理 final 与缓存。按可侵入性、性能与环引用强弱权衡选择。

123深挖

如何彻底实现深拷贝并正确处理循环引用（cycle）？

递归遍历对象图时维护已访问对象到拷贝结果的映射（如 IdentityHashMap），再遇环时复用映射中的拷贝避免无限递归；对引用字段逐字段递归复制，从而正确复制闭环对象图。

124深挖

equals 与 hashCode 在 HashMap 作为 key 时的协同机制是怎样的？

HashMap 先按 hashCode() 算桶下标，再用 equals() 判碰撞（链表或红黑树）。故 equals 相同必须 hashCode 相同，否则对象散落不同桶无法命中；同桶命中与否由 equals 决定。

通过方法引用（method reference）实现的函数式接口依赖什么机制？请结合 TreeSet 去重举例。

Collection 接口与 Map 接口在集合框架顶层结构上有何区别？

Collection 与 Map 是 Java Collections Framework 的两大顶级分支。Collection 是单列元素集合，代表一组独立对象，含 List、Set、Queue 等子接口；Map 是键值对集合，存 Entry(key,value)。两者互不继承，但 Set 与 Map 内部结构常同源，如 HashSet 底层就是 HashMap。

Collection 接口和 Collections 工具类是什么关系？

Collection 是集合框架顶层接口，List、Set、Queue 都继承它，定义 add、remove、size 等抽象方法；Collections 是 java.util 下的工具类，提供排序(sort)、反转(reverse)、同步包装(synchronizedList)、不可变集合(unmodifiableList)等静态方法，两者是接口与工具箱的关系。

133基础

List、Set、Queue 三者的核心差异是什么？

List 有序且允许重复，可按下标随机访问，如 ArrayList、LinkedList；Set 不允许重复元素，靠 equals/hashCode 判重，如 HashSet、TreeSet；Queue 遵循 FIFO(除 PriorityQueue 按优先级)，支持 offer/poll 取队首。三者均继承 Collection。

134基础

ArrayList 与 LinkedList 的区别是什么，各自适用场景是什么？

ArrayList 底层是 Object[] 动态数组，随机访问下标为 O(1)，但中间插入删除需搬移元素为 O(n)；LinkedList 是双向链表，头尾插入 O(1)，随机访问为 O(n)。随机访问多用 ArrayList，高频头尾增删可用 LinkedList。

说说 ArrayList 的默认初始容量是多少？

ArrayList 默认初始容量为 10，即在 DEFAULTCAPACITY_EMPTY_ELEMENTDATA 基础上首次 add 时按默认容量扩容到 10。之后元素数超过容量会按 grow 扩容。若已知元素规模，可用带 initialCapacity 的构造器减少扩容次数。

136基础

HashSet 是如何实现去重的？

HashSet 底层维护一个 HashMap，把元素作为 key、固定 Object 常量作为 value。去重的关键是 key 的 hashCode 决定存储桶，再通过 equals 判断桶内是否已有相同对象。因此自定义对象放入 HashSet 必须正确重写 equals 和 hashCode。

137基础

HashMap 的基本数据结构是什么？

HashMap 底层是 数组+链表+红黑树 结构：键的 hashCode 经扰动后散列到桶数组(Node[] table)下标，冲突时用链表挂接，当链表长度达到树化阈值(8)且数组容量>=64 时转为红黑树以降低查询复杂度。

138基础

Map 的 key 是如何保证唯一性的？

Map 通过 key 的 hashCode 定位桶，再用 equals 判断桶内是否已有相同 key。若已存在则覆盖 value，否则新增节点。因此重写 equals 必须同步重写 hashCode，否则可能出现 hashCode 不同但 equals 相同导致重复。

Iterator 在集合遍历中起什么作用？

Iterator 是统一的迭代器接口，提供 hasNext/next/remove，将遍历逻辑与具体集合解耦，支持安全地移除当前元素。所有 Collection 都可拿到 iterator；ListIterator 是其对 List 的扩展，支持逆向遍历与 set/add。

为什么说 ArrayList 比原生数组更方便，代价是什么？

ArrayList 封装了可变数组的扩容与增删逻辑，支持动态增长、泛型、迭代器与集合操作；代价是每次扩容涉及数组拷贝，且访问需拆箱/装箱(对基本类型)与一定内存开销。追求极值性能的数组固定场景仍可直接用原生数组。

141基础

Queue 和 Deque 的区别是什么？

Queue 是单端队列，支持 offer/poll/peek，先进先出(FIFO)；Deque 是双端队列，头部尾部皆可 offer/remove，可作栈或队列使用，ArrayDeque、LinkedList 实现了它。二者默认头插法都禁止 null 元素(实现相关)。

142基础

为什么开发中不推荐使用 Stack 类？

java.util.Stack 继承 Vector，线程安全但性能差，且基于数组实现支持按下标访问，破坏了栈的语义。官方推荐用 ArrayDeque 或 Deque 接口替代 Stack，它们更灵活高效，若无并发需求应避免用 Vector 系。

143基础

HashSet 和 TreeSet 在使用上有何不同？

HashSet 基于哈希，增删查平均 O(1)，无序且允许 null；TreeSet 基于红黑树(NavigableMap)，元素需实现 Comparable 或传入 Comparator，保证有序，增删查为 O(log n)，不允许 null。需要排序用 TreeSet，否则优先 HashSet。

144基础

equals 与 hashCode 有怎样的约定关系？

约定是：若两个对象 equals 相等，则 hashCode 必须相等；反之 hashCode 相等，equals 不一定相等。这是哈希表(HashMap/HashSet)正确工作的前提。重写 equals 时务必重写 hashCode，否则对象会因桶混乱而无法正确判重。

145基础

泛型 ? extends E 和 ? super E 有什么区别？

? extends E 限定上界，可读取但不可写入(除 null)，适合生产者，即从集合读出 E 类型；? super E 限定下界，可写入 E 但不可安全读取，适合消费者，即向集合放入 E 类型。这是泛型通配符的 PECS 原则。

146基础

增强 for 循环(for-each)在集合上是怎么实现的？

对实现 Iterable 的集合，增强 for 会被编译器翻译成显式的 Iterator 遍历(hasNext+next)，并隐式调用 iterator()。对数组则翻译为普通下标循环。因此 for-each 遍历时不能直接修改集合结构，否则会触发 fail-fast。

147基础

List.of / Set.of / Map.of 有什么特点？

它们创建持久化不可变集合(immutable collections)，不可新增、删除、修改元素，任何修改操作都抛 UnsupportedOperationException。它们也不允许 null 元素。因不可变故内部实现优化、节省内存，适合常量集合与线程安全场景。

148基础

List 默认的 removeIf 方法有什么用？

removeIf 是 Collection 的默认方法(default method)，接收 Predicate，遍历时删除满足条件的元素。实现基于迭代器并调用其 remove，因此对 ArrayList 等可安全地批量删除，从 JDK 8 起可用，替代易引发并发异常的手写循环删除。

149进阶

ArrayList 的扩容机制(grow)是怎样的，为什么是 1.5 倍？

当元素数超过容量时，grow 会把新容量设为 旧容量+(旧容量>>1)，即约 1.5 倍，并做数组拷贝。1.5 倍兼顾扩容频率与空间浪费，避免指数级浪费又减少拷贝次数。新增元素采用 add 尾部均摊复杂度仍是 O(1)。

150进阶

什么是 fail-fast，ConcurrentModificationException 是如何产生的？

fail-fast 指集合在迭代中被并发/结构性修改(增删元素)时，立即抛出 ConcurrentModificationException 而非继续执行。其依据是 modCount 字段：每个修改操作都会加一，迭代器持有期望值 expectedModCount，next 时若二者不等即抛异常。

151进阶

modCount 与 expectedModCount 在迭代中扮演什么角色？

modCount 记录集合结构性修改的次数(增删、clear、扩容等不改变元素值的 set 不算)；迭代器创建时快照 expectedModCount，每次 next/hasNext 都校验二者一致，不一致即认为其他线程或代码并发修改，抛 ConcurrentModificationException。

152进阶

HashMap 的 hash 扰动是如何进行的？

JDK8 中 key 的 hashCode 先做扰动：h ^ (h >>> 16)，即让高 16 位参与到低 16 位的计算，再与 (n-1) 做与运算得到桶下标。扰动让高位特征也能影响低位，减少散列冲突，使分布更均匀。

153进阶

HashMap 扩容(resize)时是如何 rehash 的？

当 size 超过 容量*负载因子 时，容量翻倍。JDK8 扩容时元素所在桶若为链表，其高位位不同会造成 newIndex = 原index 或 原index+旧容量(取决于扩展位是否为1)，无需重新计算 index。红黑树拆分后长度<6 会退化为链表。

154进阶

HashMap 的负载因子(loadFactor)默认是多少，有什么影响？

默认负载因子为 0.75，是时间与空间的折中：过小导致过早扩容、空间浪费但冲突少；过大会减少扩容、冲突增多、查询变慢。阈值 threshold=容量*loadFactor 决定何时扩容。可在构造器自定义以适配高内存或高空间场景。

155进阶

HashMap、Hashtable 在什么方面不同？

HashMap 非线程安全、允许 null 的 key/value、JDK8 起支持树化；Hashtable 线程安全(用 synchronized 锁整个表)、不允许 null、未树化性能差。现代并发场景用 ConcurrentHashMap 替代 Hashtable，单线程场景用 HashMap。

156进阶

HashMap 与 ConcurrentHashMap 如何选择？

单线程访问选 HashMap，性能最好；多线程并发读写下互斥且要求性能时选 ConcurrentHashMap，它通过分段/最小化锁粒度实现高并发，读操作基本无锁。不要用 Hashtable 或手动 synchronized(HashMap) 做并发容器。

157进阶

TreeMap 是如何实现排序(key 有序)的？

TreeMap 底层是红黑树(red-black tree)，key 必须实现 Comparable 或构造时传入 Comparator。插入、删除、查询均为 O(log n)，通过比较器维护 key 的顺序并保持红黑树自平衡。它实现了 NavigableMap，可做范围查询。

158进阶

TreeSet 排序与 Comparable、Comparator 有什么关系？

TreeSet 基于 TreeMap 实现，靠自然顺序(Comparable 的 compareTo)或构造时传入的 Comparator 排序。去重也由比较器决定：若 compareTo/compare 返回 0 视为相同元素。因此排序与判重都依赖比较器，是唯一判据。

159进阶

LinkedHashMap 是如何实现 LRU 的？

LinkedHashMap 维护双向链表记录插入顺序或访问顺序。构造时设 accessOrder=true 即可按访问顺序排列，每次 get/put 命中会用 afterNodeAccess 把节点移到末尾，最早访问(未被访问)的位于头部，配合 removeEldestEntry 可做 LRU 缓存。

160进阶

PriorityQueue 的实现原理是什么？

PriorityQueue 基于二叉堆(最小堆)实现，默认按自然顺序取最小元素，也可传 Comparator。offer 上浮(siftUp)、poll 下沉(siftDown)，均为 O(log n)，peek 为 O(1)。它不保证整体有序，只保证堆顶是最小值。

请列举几个常用的 Collections 工具类方法。

常用有 sort 排序、binarySearch 二分查找、reverse 反转、shuffle 打乱、rotate 旋转、synchronizedList/Map 同步包装、unmodifiableList/Map 只读包装、emptyList/singletonList 等。它们以静态方法形式对集合做通用操作。

162进阶

在遍历 ArrayList 时如何安全地删除元素？

直接 for-each 中调用 list.remove() 会因 modCount 变化触发 ConcurrentModificationException。安全方式：用 iterator 的 iterator.remove() 逐个删除，或用 removeIf(Predicate)，两者都是基于迭代器安全删除，不会抛异常。

163进阶

HashSet、LinkedHashSet、TreeSet 如何选型？

只需去重、不关心顺序选 HashSet(哈希，O(1))；需要保持插入顺序选 LinkedHashSet(双向链表维护顺序)；需要按元素排序选 TreeSet(红黑树，O(log n))。顺序要求与性能是主要取舍因素。

164进阶

为什么 HashMap 的 key 是可变的会带来风险？

HashMap 用 key 的 hashCode 计算桶位置。若 key 放入后被修改导致 hashCode 变化，则原桶下标失效，修改后无法通过新 hashCode 找到原节点，造成元素丢失(不可访问)。因此尽量用不可变对象(如 String、Integer)作为 key。

165进阶

ArrayList 的 subList 是什么，有什么注意事项？

subList(from,to) 返回的是原列表的视图(view)，而非新副本，对 subList 的修改会反映到原列表。原理是 SubList 持有原列表引用与 offset，其结构修改会同步原列表 modCount。对原列表结构修改后再用 subList 会抛并发异常。

166进阶

重写 equals 和 hashCode 需要遵循哪些规范？

equals 需满足自反、对称、传递、一致且与 null 比较为 false，且使用同一组字段；hashCode 须保证 equals 相等则 hashCode 相等，且对不变字段计算。可用 Objects.equals/Objects.hash 或 IDE 生成，保持两者字段一致。

Arrays.asList 返回的 List 有什么陷阱？

Arrays.asList 返回固定大小、由数组支撑的 List，底层引用原数组，修改数组会反映到 List；不支持 add/remove，否则抛 UnsupportedOperationException；元素类型为基本类型数组时(如 int[])，List 元素是整个数组而非每个元素。

Iterator 和 ListIterator 有什么区别？

Iterator 是所有 Collection 通用的迭代器，仅支持正向遍历与 remove；ListIterator 专用于 List，额外支持逆向遍历(hasPrevious/previous)、set 替换元素、add 插入，并可获取当前索引。需要向后遍历或修改时用 ListIterator。

HashMap 中链表转红黑树、红黑树退化的条件是什么？

当某桶链表长度达到阈值 8(TREEIFY_THRESHOLD) 且数组容量>=64(MIN_TREEIFY_CAPACITY) 时转红黑树；若容量<64 则先扩容而非树化。扩容拆分后，若该桶节点数降到 6(UNTREEIFY_THRESHOLD) 以下，红黑树会退化为链表。

JDK7 中 HashMap 并发扩容为何会形成环形链表死链？

JDK7 扩容用头插法(transfer)迁移旧桶元素，处于并发执行时，多线程同时 rehash 可能造成同一节点被反复迁移，指针相互引用形成环形链表(死链)，导致 get 时无限循环(死循环) CPU 飙升。JDK8 改用尾插法规避了该问题。

171深挖

ConcurrentHashMap 在 JDK7 与 JDK8 的差别是什么？

JDK7 采用分段锁(Segment)数组，锁粒度是 Segment(默认 16 段)；JDK8 弃用 Segment，改为 数组+链表+红黑树，用 CAS 在空桶抢占(volatile 配合 Unsafe)，桶冲突时对桶头节点 synchronized 加锁，锁粒度更细、支持扩容并发。

172深挖

ConcurrentHashMap 的 size() 是如何统计的？

JDK8 用分散计数：维护 baseCount 与 CounterCell 数组，多线程更新时 CAS 到 baseCount，冲突则分散到 CounterCell 缓解竞争。size() 合并 baseCount 与各 CounterCell 累加，最终用 sumCount 得到近似准确值。

173深挖

TreeMap 底层红黑树的五条性质你还记得吗？

红黑树性质：每个节点非红即黑；根为黑；每个叶子(NIL)为黑；红色节点的子节点必须为黑(不能连续红)；从任一节点到其每个叶子的路径包含相同数目的黑节点。TreeMap 靠这些约束+旋转保持 O(log n) 平衡。

174深挖

PriorityQueue 的堆化与插入、删除元素的过程是怎样的？

PriorityQueue 用数组存储二叉最小堆，插入(offer)把新元素放末尾并 siftUp 上浮，删除堆顶(poll)把末尾节点移到堆顶并 siftDown 下沉比较。无序数组建堆用 heapify 自底向上 siftDown，复杂度为 O(n)。

175深挖

fail-fast 与 fail-safe 集合有何区别？

fail-fast(如 HashMap、ArrayList)迭代中结构修改立即抛 ConcurrentModificationException；fail-safe(如 CopyOnWriteArrayList、ConcurrentSkipListMap)迭代基于“快照/副本”，修改不影响已获得的迭代器，不抛异常，但牺牲一致性且部分操作有复制开销。

176深挖

HashMap 为什么要求容量为 2 的幂次方？

容量恒为 2^n 是为了用 (n-1) & hash 位运算替代取模，提高效率且散列更均匀；也便于扩容时容量翻倍和链表按高位位拆分。构造函数传入非幂值也会被 tableSizeFor 规范化为不小于它、最近的 2 的幂次。

177深挖

多线程环境下为何 HashMap 会数据错乱、需要如何选型？

HashMap 非线程安全，多线程并发 put/resize 会造成数据丢失、覆盖、甚至(JDK7)环形链表死循环。选型上：并发读多写少可用 ConcurrentHashMap；需有序可用 ConcurrentSkipListMap；对一致性要求高可加锁或使用同步容器。

178深挖

NavigableMap(TreeMap)提供了哪些范围查询能力？

NavigableMap 提供 lowerEntry/floorEntry/ceilingEntry/higherEntry 及对应 key，subMap/headMap/tailMap 截取区间视图，还有 firstEntry/lastEntry、descendingMap 逆序视图。这些基于红黑树的中序，用于键区间的高效查找。

179深挖

WeakHashMap 的作用与适用场景是什么？

WeakHashMap 的 key 采用弱引用(WeakReference)，当 key 不再被强引用时，GC 会回收该 key，对应 Entry 在下次操作时被清除。常用来做简易缓存(如记录字符串元数据)，避免内存泄漏。其 value 为强引用，注意 value 反向引用 key 的循环。

180深挖

ArrayDeque 与 LinkedList 用作队列/栈时如何选择？

ArrayDeque 底层是循环数组，支持高效头尾插入删除，随机访问快，不允许 null 且容量可自动增长；LinkedList 是链表，插入无需搬移但节点开销大、缓存局部性差。作队列/栈推荐 ArrayDeque，随 OS 字节操作也略优。

Java 中异常和错误的顶层父类分别是什么？

Throwable 是异常与错误的父类，其下分 Error 和 Exception。Error 表示 JVM 严重问题（如 OutOfMemoryError、StackOverflowError），不可恢复、不应捕获；Exception 是程序可处理的异常，应 try-catch 或 throws 处理。

182基础

什么是 Checked Exception（受检异常）和 Unchecked Exception（非受检异常）？

受检异常编译期强制处理，必须 try-catch 或 throws 声明，如 IOException、SQLException，直接继承 Exception。非受检异常指 RuntimeException 及其子类（如 NullPointerException）以及 Error，编译期不强制处理。

183基础

如何自定义一个异常类？

自定义异常通常继承 Exception（成为受检）或 RuntimeException（成为非受检），通过 super 调用父类构造器传入 message 与 cause。抛出后可传递错误信息和原因链，便于上层捕获定位。

184基础

finally 块和 return 的执行顺序是怎样的？finally 中的 return 会怎样？

正常情况下 try 中的 return 先计算出返回值，再进入 finally 执行，最终返回外层。若 finally 也写了 return，会覆盖 try 的返回值并可能吞掉异常，属危险写法，应避免在 finally 中 return。

185基础

抛出和捕获异常对性能有什么影响？

创建并抛出异常会填充 StackTrace、抓取堆栈，开销很大，频繁抛出会显著影响性能。所以正常控制流程应用条件判断代替异常，异常只用于真正的错误场景。

186进阶

谈谈 BIO、NIO、AIO 的区别。

BIO 是阻塞式 I/O，一个连接对应一个线程，读写时阻塞；NIO 是同步非阻塞 I/O，基于 Channel 和 Buffer，借助 Selector 单线程可管理大量连接；AIO 是异步非阻塞 I/O，完成后回调。BIO 简单但吞吐低，NIO 适合高并发。

187进阶

请介绍 NIO 的核心组件 Channel、Buffer、Selector 分别的作用。

Channel 是双向传输通道（如 FileChannel、SocketChannel）；Buffer 是缓冲区，管理 position、limit、capacity；Selector 通过多路复用监听多个 Channel 的就绪事件，使单线程能处理多连接，三者共同支撑 NIO 非阻塞模型。

188进阶

FileInputStream 和 FileReader 有什么区别，如何选型？

FileInputStream 是字节流，按字节读取，适合二进制文件；FileReader 是字符流，按字符读取并按编码解码，适合文本文件。选型看数据类型：文本用 Reader（可包 BufferedReader），二进制必须用字节流。

189进阶

new InputStreamReader 时为什么要指定字符集？

InputStreamReader 负责把字节按字符集解码为字符。若不指定则用平台默认编码，可能乱码且跨平台结果不一致。所以应显式指定 UTF-8 等字符集以保证正确解码。

190进阶

BufferedReader/BufferedWriter 的作用是什么？

它们为字符流提供缓冲，减少底层系统调用次数，提升读写效率；同时 BufferedReader 提供 readLine() 按行读取的能力，是高效处理文本文件的常用方式。

191进阶

什么是序列化？一个对象要能被序列化需要满足什么条件？

序列化是把对象转成字节流以便存储或传输，反序列化是逆过程。类需实现 Serializable 接口；static 字段不参与；serialVersionUID 用于版本校验，缺失或不一致可能抛 InvalidClassException。

192进阶

transient 关键字的作用是什么？

transient 修饰的字段不会被默认序列化机制写入，常用于敏感信息（如密码）或无需序列化的临时字段。它只影响默认序列化，若自定义 writeObject 则不受影响。

193进阶

什么是零拷贝？Java 中如何实现？

零拷贝指避免数据多次在内核态与用户态间拷贝，减少 CPU 开销与上下文切换。Linux 用 sendfile；Java 可通过 FileChannel.transferTo()/transferFrom() 在内核空间完成文件到套接字的传输，提升性能。

194深挖

JDK 中 try-with-resources 的原理是什么？适合什么场景？

它自动关闭实现了 AutoCloseable/Closeable 的资源，编译后等价于在 finally 中调用 close()，且关闭异常通过 addSuppressed 抑制保留主异常。适合自动管理文件、流、连接等需要释放资源的场景。

195深挖

如何避免在 finally 中关闭流时掩盖原始异常？

优先使用 try-with-resources，它用 addSuppressed 保留主异常并附带关闭异常。若手写 finally，应捕获 close 抛出的异常并 addSuppressed 到原异常，而不是直接覆盖，从而保留完整异常链便于排查。

196深挖

多异常合并捕获时应该注意什么？

可用 catch (IOException | SQLException e) 合并捕获，前提是这些异常无父子继承关系，合并后 e 类型取公共父类，只能使用公共父类上的方法。这样减少冗余，但要避免误吞异常。

197深挖

NIO 中 Selector 和零拷贝分别解决什么问题？

Selector 基于多路复用解决高并发连接数问题，单线程监听大量 Channel 的就绪事件，降低线程开销；零拷贝面向大数据量传输，减少内存拷贝。二者分别优化并发握手与数据传输，是高性能网络服务的常用手段。

198深挖

字符编码中 UTF-8 和 UTF-16 有什么本质区别，如何影响 I/O？

UTF-8 是变长编码，ASCII 用 1 字节、中文用 3 字节，兼容 ASCII 且省空间；UTF-16 以 2 或 4 字节为单位，索引方便但有字节序和空间开销。读写必须指定一致编码，否则会乱码或数据损坏。

199深挖

try-catch-finally 中若 catch 抛出新异常，finally 还执行吗？原异常如何处理？

finally 仍会执行，在方法退出前必定运行。随后抛出 catch 抛出的新异常，原异常被丢弃；若用 try-with-resources 则被 addSuppressed 保留。因此应把原异常加入 suppressed 以免丢失根因。

200深挖

读取大文件时逐字节 read() 与块读 read(byte[]) 的性能差异在哪？

read() 逐字节调用底层读取，方法调用与系统调用频繁，开销大；read(byte[]) 一次性读入数组，减少调用次数、吞吐更高。读大文件应尽量用带缓冲或块读接口（如 BufferedReader、read(byte[],off,len)）。

201基础

线程与进程的区别是什么？

进程是资源分配的最小单位，拥有独立地址空间与堆栈；线程是CPU调度的最小单位，是进程内一条执行路径，同进程线程共享堆、独占栈。线程切换成本更低，并发提升CPU利用率，但也引入线程安全问题。

202基础

说一下线程的生命周期，Java中线程有哪六种状态？

Thread.State定义：NEW、RUNNABLE（就绪/运行）、BLOCKED（阻塞在锁）、WAITING（如wait/join/Park）、TIMED_WAITING（如sleep/parkNanos）、TERMINATED。运行中归为RUNNABLE。

203基础

线程六种状态之间是如何转换的？

start使NEW转RUNNABLE；抢锁失败进BLOCKED，获锁回RUNNABLE；wait/join/park进WAITING，notify/unpark唤醒回RUNNABLE；sleep或带超时wait进TIMED_WAITING；结束或异常进TERMINATED。

204基础

为什么需要多线程？

提升资源利用率和吞吐：利用多核CPU并行、任务并发执行缩短响应时间，阻塞时让出CPU。同时提升用户体验。代价是竞态、死锁、上下文切换开销，需正确并发控制并权衡收益。

205基础

创建线程有哪几种方式？

三种：继承Thread重写run；实现Runnable传入Thread；实现Callable配FutureTask获取返回值。后两种更优，因Java单继承、实现接口更灵活。本质都需创建Thread并调用start启动。

206基础

Runnable 与 Callable 有什么区别？

Runnable的run无返回值、不抛异常；Callable的call返回泛型结果且可抛受检异常。Callable常配FutureTask，经future.get取结果或异常。需要计算结果的场景用Callable。

207基础

Thread、Runnable、Callable 三者对比有什么结论？

不推荐直接继承Thread，它耦合逻辑与线程控制；不需要返回值用Runnable，需返回值用Callable。二者都解耦任务与线程、便于线程池复用，选择取决于是否需结果与异常处理。

208基础

调用 start() 与直接调用 run() 有什么区别？

start()创建新线程异步执行run，实现真正并发；直接调run()只是调用线程内普通同步方法调用，不开启新线程。必须用start()启动线程，且start只能调用一次。

209基础

直接调用 run() 会出现什么问题？

run()被当普通方法在当前线程同步执行，无新线程、并发失效；重复start抛IllegalThreadStateException，而直接调run只是顺序多次执行，掩盖线程未启动的Bug。正确方式是start()。

210基础

sleep() 和 wait() 有什么区别？

sleep是Thread静态方法，不释放锁、自动醒转；wait是Object实例方法，须持有监视器锁，调用后释放锁进入WAITING，靠notify/notifyAll唤醒。sleep让步，wait协调等待通知。

211基础

yield() 的作用是什么？

yield提示调度器当前线程让出CPU，让他线程有机会运行，但不保证一定让出且不释放锁。是软提示，依赖调度器，主要用于测试或轻量让步，生产环境较少依赖。

212基础

join() 的作用是什么？

t.join()使当前线程等t执行完再继续，进入WAITING或限时等待，t结束后恢复。常作主线程等待子线程结果，可用CountDownLatch实现更细粒度控制。

213基础

什么是线程安全？

多线程访问共享数据时，无需额外同步就能保证结果正确、无竞态破坏，即线程安全。实现途径包括synchronized、Lock、volatile、原子类、不可变对象、ThreadLocal等，目标是原子性、可见性、有序性。

214基础

synchronized 修饰方法和方法块有什么区别？

同步实例方法锁this；同步静态方法锁Class对象；同步块可指定任意锁，粒度灵活、可缩小临界区。静态与实例锁对象不同故可并发。选择决定锁粒度。

215基础

什么是对象锁和类锁？

对象锁以某个实例为监视器锁（如synchronized(this)）；类锁以Class对象为锁（如静态同步方法）。二者是不同锁互不阻塞。锁本质是monitor，关联对象头Mark Word。

216基础

什么是可重入锁？

可重入指同一线程已持有某锁时还能再获取同锁不死锁，获取计数递增、释放递减。synchronized和ReentrantLock都支持，使递归或在锁内再调加锁方法安全。实现记录持有线程与计数。

217基础

volatile 关键字的作用是什么？

volatile保证可见性与有序性：写立即刷到主内存在多核可见，读从主存取，并通过内存屏障禁止重排序。但它不保证原子性，复合操作如i++仍需锁或原子类，典型用于状态标志位。

218基础

并发编程的三大特性是什么？

原子性：操作不可分割，靠锁与CAS；可见性：修改对其他线程可见，靠volatile、synchronized与锁；有序性：执行不被乱序破坏，靠synchronized、volatile与happens-before约束。volatile解决可见性与有序性。

219基础

什么是原子类？

原子类位于java.util.concurrent.atomic，基于CAS与自旋实现原子操作，如AtomicInteger、AtomicLong、AtomicBoolean、AtomicReference。免锁实现读改写原子，适合计数器、累加等简单场景。

220基础

ThreadLocal 的基本作用是什么？

ThreadLocal为每线程维护独立副本，实现线程间隔离。底层每个Thread持有ThreadLocalMap，以ThreadLocal为key。常用于上下文传递、用户会话、Non线程安全对象（如SimpleDateFormat）隔离。

221基础

Object 的 wait/notify 是干什么用的？

wait释放锁进入WAITING等待队列；notify/notifyAll唤醒等待线程后重新抢锁。必须成对用于生产者-消费者等协调场景，是synchronized时代底层的等待通知机制。

222基础

什么是死锁？

死锁指多线程互相持有对方所需资源并永久等待。四条件：互斥、持有并等待、不可剥夺、循环等待，破坏任一可解除。程序会假死，排查用jstack转储线程栈定位互相等待的锁。

223基础

线程池的作用和好处是什么？

池化复用线程，避免频繁创建销毁开销；统一管理线程数、生命周期与并发上限，防资源耗尽；提供队列、拒绝策略、监控。核心是ThreadPoolExecutor，提升吞吐与稳定性。

224基础

ThreadPoolExecutor 的核心参数有哪些？

七大参数：corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler（RejectedExecutionHandler）。提交超core入队，队满且超max走拒绝策略。

225基础

线程池 execute() 和 submit() 有什么区别？

execute只跑Runnable无返回，异常自行捕获；submit提交Runnable或Callable返回Future，可拿结果、异常封装进Future。submit能力更强，底层用FutureTask包装，通常用submit管理任务。

226基础

FutureTask 的作用是什么？

FutureTask实现RunnableFuture，既可作Runnable执行又可作Future取结果。get阻塞等待结果，支持取消与超时，结果缓存复用，适合有返回值的异步任务，常配Callable。

227基础

CountDownLatch 的作用是什么？

CountDownLatch让一个或多个线程等其余线程完成一组操作后继续，构造传计数n，countDown递减，await阻塞到零。一次性门闩不可复用。典型：主线程等若干子任务完成后汇总。

228基础

CyclicBarrier 的作用是什么？

CyclicBarrier让一组线程相互等待，全部到达屏障点才放行。await等待，计数满触发barrierAction且自动重置可循环使用。适合分阶段计算的相互同步。

229基础

Semaphore 的作用是什么？

Semaphore是计数信号量，控制同时访问资源数量，acquire取许可不足则阻塞，release归还。可作限流与资源池控制，重点在并发量控制而非线程对齐。

230基础

CountDownLatch、CyclicBarrier、Semaphore 有什么区别？

CountDownLatch计数归零放行、一次性，强调一方等待；CyclicBarrier线程互相对齐、全到才继续且可循环；Semaphore靠许可控制并发量。三者语义、复用性、用途不同，按场景选用。

231基础

Java 中有哪些并发容器？

在java.util.concurrent：ConcurrentHashMap、CopyOnWriteArrayList、ConcurrentLinkedQueue及阻塞队列BlockingQueue系列（ArrayBlockingQueue、LinkedBlockingQueue、SynchronousQueue、DelayQueue）、ConcurrentSkipListMap等。

232基础

notify 和 notifyAll 有什么区别？

notify随机唤醒一个等待线程，notifyAll唤醒全部再抢锁。等待者多时notify可能遗漏致假死，故多用notifyAll。唤醒本质是WAITING回RUNNABLE抢锁，均须在持锁代码块内调用。

233基础

什么是守护线程？

守护线程服务于其他线程，如GC，当所有非守护用户线程结束后JVM退出并终止守护线程。setDaemon(true)可设为守护线程，须在start前调用。JVM退出标志是非守护线程是否全结束。

234基础

sleep() 为什么不释放锁？

sleep只是暂停当前线程一段时间，锁仍被持有，其他线程只能等待，这与wait释放锁不同。sleep是纯时间让步，不进入等待通知，避免临界区不一致，故不释放占用锁。

235基础

线程不安全的典型例子有哪些？

典型：HashMap并发put丢数据、SimpleDateFormat日期错乱、ArrayList并发add越界、StringBuilder并发互覆盖、i++自增丢更新、未同步的单例。均为共享可变状态无同步被并发访问的竞态。

236进阶

synchronized 的底层原理和锁升级过程是怎样的？

synchronized基于monitor（Mark Word上的监视器），JDK1.6优化为偏向锁、轻量级锁、重量级锁逐级升级。无竞争偏向锁，轻微竞争CAS+Lock Record轻量级锁，激烈膨胀为OS mutex重量级锁，只能升级不能降级。

237进阶

volatile 和 synchronized 有什么区别？

volatile只保证可见性与有序性，不保证原子性，无锁开销小，适用标志位与double-check；synchronized是互斥锁，既保原子又保可见，但成本高可能阻塞。需要复合原子操作用锁或原子类。

238进阶

volatile 能保证原子性吗？为什么 i++ 不安全？

不能。i++是读-改-写三步，volatile只保证每步可见性，无法整体原子，两线程同值自增会丢更新。安全自增用AtomicInteger或synchronized。volatile适合纯读写标志位，不适复合运算。

239进阶

什么是 happens-before 规则？

happens-before是JMM的可见性排序规则，前操作结果对后操作可见。主要规则：程序次序、监视器锁、volatile写-读、线程start、线程join、传递性。是判断并发安全的关键依据。

240进阶

volatile 是如何保证可见性的，谈谈 MESI 缓存一致性协议？

volatile写经内存屏障+缓存一致性协议（MESI）多核同步。MESI用Modified/Exclusive/Shared/Invalid维护缓存行，某核修改置Invalid并通知他核，volatile读重新加载，结合屏障禁重排，实现可见性。

241进阶

说一下 CAS 的原理与优缺点？

CAS（Compare And Swap）是原子指令，比较内存值与期望值，相等换新值，否则不更新，硬件由CPU与Unsafe保证。优点无锁开销小；缺点自旋不一定成功、有ABA、只对单变量原子。

242进阶

CAS 的三大问题是什么？如何解决？

ABA问题用AtomicStampedReference加版本戳解决；自旋过长CPU空转用LongAdder分段或限次缓解；只能单变量原子，多变量用锁或AtomicReference组合包装。

243进阶

自旋锁是什么？适用于什么场景？

自旋锁拿不到锁时原地CAS忙等而非阻塞。适合锁持有短、竞争弱场景，避免挂起唤醒的上下文切换开销。自旋久浪费CPU，有自适应自旋调整次数，JUC原子类基于自旋。

244进阶

AtomicInteger 的底层实现原理？

AtomicInteger内部volatile int保证可见性，compareAndSet调Unsafe的CAS更新，失败循环重试。getAndIncrement等基于CAS自旋原子自增，用volatile+CAS实现无锁原子更新，依赖处理器原子指令。

245进阶

LongAdder 的原理和适用场景？

LongAdder采用热点分离：内部base与多个Cell，冲突时分散到不同Cell自增，sum累加所有Cell。减少CAS竞争、吞吐高但sum非强一致，适合写多读少的高并发累加，Java8引入。

246进阶

ReentrantLock 基本用法和特点是什么？

ReentrantLock是可重入互斥锁，基于AQS。需显式lock加锁、unlock释放，配try/finally。支持公平/非公平、可中断、超时获取、多Condition，比synchronized灵活但需手动释放。

247进阶

ReentrantLock 与 synchronized 有什么区别？

synchronized自动加解锁、非公平、不可中断、单一等待队列；ReentrantLock手动加解锁，支持公平、响应中断、tryLock超时、多Condition。需公平或可中断用ReentrantLock，否则用synchronized更简洁。

248进阶

Lock 接口提供哪些主要方法？

lock()阻塞获取；lockInterruptibly()可中断获取；tryLock()非阻塞尝试返回布尔并可带超时；unlock()释放。配合Condition的await/signal实现等待通知。ReentrantLock是主要实现，用前成对释放。

249进阶

什么是公平锁和非公平锁？

公平锁按请求顺序排队先到先得，不饥饿但吞吐低；非公平锁允许插队，吞吐高但可能饥饿。ReentrantLock默认非公平可传fair=true，synchronized只能非公平。排队由AQS的FIFO队列实现。

250进阶

AQS 的核心原理是什么？

AQS（AbstractQueuedSynchronizer）用volatile state加CLH双向队列管理等待线程。获取用CAS改state，失败入队并park挂起，释放唤醒后继。支持独占（ReentrantLock）与共享（Semaphore等）两种模式，是JUC基石。

251进阶

ReentrantLock 是如何实现可重入的？

ReentrantLock内部是state计数+owner持有线程记录。加锁时若当前线程已是持有者state+1直接成功；释放时state-1归零才真正释放唤醒他线程。同线程多次加锁不阻塞，计数归零才释放。

252进阶

什么是上下文切换？为什么有开销？

上下文切换是CPU从一线程切到另一线程时保存寄存器、程序计数器、栈并加载新线程状态。开销来自保存恢复、用户态内核态切换、缓存失效重载、调度。线程数远超核数时切换频繁降效率。

253进阶

ThreadLocal 的实现原理是什么？

ThreadLocal并不自己存数据，而是每个Thread持有ThreadLocalMap，以ThreadLocal的弱引用为key。线程访问以自身map取值实现隔离，set/get操作当前线程的map，天然隔离免同步。

254进阶

ThreadLocal 为什么会内存泄漏？如何避免？

ThreadLocalMap的key是弱引用，外部强引用被清理后key可被GC，但value仍被map强引用持有，线程不结束则value泄漏。用后remove()清除，线程池复用场景必须remove。

255进阶

线程池的任务执行流程是怎样的？

提交后：线程数小于core建核心线程执行；达core且队未满则入队；队满且小于max建非核心线程；都满执行拒绝策略。keepAliveTime回收空闲非核心线程。顺序core→队列→max→拒绝。

256进阶

线程池的四种拒绝策略分别是什么？

AbortPolicy抛RejectedExecutionException（默认）；CallerRunsPolicy由提交线程运行任务降速反压；DiscardPolicy静默丢弃；DiscardOldestPolicy丢最老任务再提交。按业务选：能丢、通知或降级。

257进阶

newCachedThreadPool 和 newFixedThreadPool 的隐患是什么？

newFixedThreadPool用无界LinkedBlockingQueue，积压会OOM；newCachedThreadPool最大线程数Integer.MAX_VALUE，任务多创建海量线程耗尽资源。官方建议用ThreadPoolExecutor显式设有限队列与max。

258进阶

如何正确设置线程池的参数？

CPU密集约核数+1；IO密集用较大线程数（核数*2或按等待占比公式）。核心尽量复用，队列要有界，max按峰值与资源上限，拒绝策略按业务选，配自定义factory命名线程。业内也会动态调整。

259进阶

wait/notify 为什么必须放在 synchronized 中？

wait释放锁并挂起、notify通知，不持监视器锁无权操作monitor，会抛IllegalMonitorStateException。同步块保证检查与挂起间不被插入避免唤醒丢失，并配while循环防虚假唤醒。

260进阶

什么是虚假唤醒？如何避免？

虚假唤醒指线程未收到notify却从wait提前返回，是底层允许行为。用while(条件)循环包住wait，醒来重查条件，不满足继续wait，生产者消费者在循环判非空再消费。

261进阶

生产者-消费者用 wait/notify 还是 BlockingQueue？

手写wait/notify需自管锁、while循环、notifyAll且易错；用BlockingQueue（如ArrayBlockingQueue）的put/take自带阻塞与通知，简洁安全。生产级推荐BlockingQueue，面试先讲原理再看封装。

262进阶

Condition 与 synchronized 的 wait/notify 有什么异同？

Condition由Lock创建，等价于wait/notify但更强：一个Lock可建多Condition精准唤醒，await支持超时与可中断。await/signal对应wait/notify，signalAll对应notifyAll。synchronized只有一等待队列。

263进阶

Future.get() 有什么要注意的？

get()阻塞等待，可用带超时get(timeout,unit)防永久阻塞；任务抛异常则get抛ExecutionException。多次get防死锁与饿死，必要时cancel。get前未完成会阻塞当前线程。

264进阶

线程池里任务抛异常会怎样？会继续执行后续任务吗？

单任务异常不使线程池挂掉，异常交给handler或封装进Future，线程继续复用执行后续任务。execute未捕获交给UncaughtExceptionHandler；submit封装进Future由get抛出。不中断其他任务。

265进阶

JMM 的主内存与工作内存模型是什么？

JMM规定线程不能直接访问主内存，须经各自工作内存（对应CPU缓存/寄存器）读改写，经主内存同步，这解释可见性问题。JMM屏蔽硬件差异，用happens-before提供一致内存语义。

266进阶

如何排查死锁？

用jstack dump线程栈：线程A持锁1等锁2、线程B持锁2等锁1即死锁；也可用jconsole可视化或探测加锁顺序。修复是打破循环等待：固定加锁顺序、tryLock超时、减小锁粒度。

267进阶

如何避免死锁？有哪些策略？

破坏死锁四条件：避免循环等待，全局一致加锁顺序；一次性申请全部资源破坏持有并等待；用tryLock带超时避免永久互等；资源ID排序加锁。配合控锁粒度与范围，从设计上避免。

268进阶

synchronized 升级为重量级锁后缺点是什么？

重量级锁依赖OS mutex，线程挂起唤醒需内核态切换，上下文切换开销大、吞吐低。Java6引入偏向锁与轻量级锁优化低竞争，只激烈时膨胀。这也是用无锁CAS/乐观并发的动因。

269进阶

什么是锁消除和锁粗化？

都是JIT优化。锁消除：JVM去掉线程私有无共享对象上的无意义锁（如局部StringBuffer）；锁粗化：把相邻多次加锁合并为更大范围（如循环反复加锁同对象），减少加解锁。自动优化不可干预。

270进阶

为什么会抛出 ConcurrentModificationException？如何避免？

普通集合迭代器fail-fast，modCount在迭代期间被并发修改就抛ConcurrentModificationException。用CopyOnWriteArrayList快照遍历、改用并发集合ConcurrentHashMap或迭代加锁。优先用juc并发集合。

271进阶

ConcurrentHashMap 为什么线程安全？JDK8 的实现如何？

JDK7用Segment分段锁，JDK8改CAS+红黑树：写对桶头节点CAS，冲突用synchronized锁头节点，超8转红黑树。读基本无锁依赖volatile。size用CounterCell。数据结构数组+链表/红黑树。

272进阶

CopyOnWriteArrayList 的原理和适用场景？

写时复制：add/set复制数组生成新数组替换volatile引用，读不加锁在旧快照读，写慢读快。适读多写少、读拿一致性快照。缺点写O(n)复制、内存翻倍，不适写密集。

273进阶

ExecutorService 中 shutdown 和 shutdownNow 区别？

shutdown让已提交任务执行完并拒绝新任务，全完成后终止；shutdownNow中断正在执行线程并返回未开始任务列表。都不保证强制终止，取决是否响应中断。shutdown优雅，shutdownNow立即。

274进阶

ConcurrentHashMap 与 Hashtable 的区别？

Hashtable对整个Map加一把synchronized锁、并发度低；ConcurrentHashMap分段/CAS+锁桶细粒度控制、读多无锁。Hashtable禁止null，CHM并发更强，现代并发首选ConcurrentHashMap。

275进阶

原子类和锁各适合什么时候用？

单个共享变量的简单读改写（计数器、标志位）用原子类CAS开销小；需保护多变量一致性、复合操作或状态机则用锁保证原子性。锁可管理任意规模临界区，选择依据临界区复杂度。

276深挖

AQS 中 CLH 队列与公平锁的实现细节？

AQS用自建双向队列，head哨兵、tail尾插，获取失败节点CAS入队并park挂起等前驱。公平锁tryAcquire检查队列是否还有等待者，有则排队；非公平先抢。释放唤醒head后继，CLH依次唤醒避免惊群。

277深挖

ReentrantReadWriteLock 与 StampedLock 的原理和选型？

ReentrantReadWriteLock读写互斥、读读共享，用state高16写低16读表示，适读多写少但可能写饥饿。StampedLock加乐观读，无写零成本、需校验，写时升级读锁，提高读吞吐，但不可重入且易用错。

278深挖

LongAdder 的 Cell 与缓存行填充如何减少竞争？

LongAdder用@sun.misc.Contended让Cell独占缓存行，避免不同Cell在同缓存行造成false sharing；冲突按hash散到不同Cell自增，降单一热点CAS自旋。sum遍历base与Cell累加，非强一致。

279深挖

volatile 写与 synchronized 释放的 happens-before 如何保证可见性？

synchronized解锁happens-before后续加锁，volatile写happens-before其读，配合传递性把跨线程写沿happens-before链传递。底层由内存屏障落地，保障可见且防重排。

280深挖

如何实现一个简单的可重入自旋锁？

用AtomicInteger做标志，加锁CAS忙等并记录持有线程与计数：是持有者则计数+1成功，解锁减到0才释放。防过度自旋与持有线程被调度暂停致他人空转，生产更推荐AQS或synchronized。

281深挖

为什么 newFixedThreadPool 用无界队列有 OOM 风险？

LinkedBlockingQueue容量默认Integer.MAX_VALUE近无限，可堆积海量任务占满堆内存OOM。队列无限使max与拒绝策略不触发、线程钉在core，高峰积压超内存即崩。必须显式限定队列容量。

282深挖

如何用有界线程池实现生产者的反压限流？

用ArrayBlockingQueue做有界缓冲，put满阻塞天然背压；或用显式有界workQueue，队满触发max扩容再到CallerRunsPolicy把任务推回调用方降速。核心是让容量成为背压信号。

283深挖

虚拟线程中 synchronized 的 pinning 问题是什么？

虚拟线程阻塞时一般把平台线程让给别人，但若持synchronized（monitor）阻塞在锁上，会把平台线程钉住pinning无法调度其他虚拟线程，反降并发。规避：虚拟线程内减少synchronized阻塞段或权衡调度。

284深挖

JUC 的 LockSupport 与 wait/notify 有什么本质区别？

park/unpark基于线程许可机制，不要求持锁、不依赖监视器，unpark可提前唤醒且不需同步块，更底层灵活可任意阻塞。AQS用park/unpark做挂起唤醒。park许可可累积但不可重入。

285深挖

描述 volatile 内存屏障在 x86 与弱内存序平台上的落地差异？

x86为TAS模型，多数普通读写同类不重排且缓存一致性保写可见，volatile屏障常被精简为StoreLoad，开销最低。弱内存序平台（ARM）需插入完整屏障以维持统一语义。

286深挖

为什么 CompletableFuture 默认用 ForkJoinPool.commonPool？要注意什么？

未指定executor用ForkJoinPool.commonPool（并行度约CPU核数），线程有限易被阻塞任务占满致future相互等待甚至饿死。阻塞或不可控任务应显式传自定义池，then*Async时指定executor。

287深挖

如何设计一个线程安全的懒加载单例？比较各实现的取舍？

静态内部类holder依赖类加载同步，天然懒且安全、开销最小；volatile double-check自行控制加锁；枚举单例由JVM保证唯一且序列化安全。生产常用holder或枚举，需初始化参数再做权衡。

288深挖

happens-before 规则有哪些？为什么线程 join 也能保证可见性？

规则含程序次序、监视器锁、volatile写-读、线程start、线程join、默认值、传递性。join后主线程在子线程结束处返回，子线程内所有写happens-before该返回点，故其写入主线程可见，等价同步边界。

289深挖

读写锁公平性选择与写饥饿如何权衡？

ReentrantReadWriteLock非公平下读多写少时写长期得不到锁即写饥饿，公平模式或fair=true可缓解。StampedLock乐观读可降低写饥饿并提读吞吐。按读写比例选，读极多且容忍短暂写延迟用乐观读。

290深挖

AbstractQueuedSynchronizer 的 tryAcquire/tryRelease 如何被用户扩展？

tryAcquire/tryRelease是模板方法由子类实现，用CAS改state判定能否获取/释放，返回布尔，失败再入队挂起。用户自定义state语义（ReentrantLock计数、Semaphore许可、CountDownLatch计数），AQS统一排队唤醒。

291深挖

线程池的队列选择对吞吐与延迟有什么影响？

LinkedBlockingQueue吞吐稳定但可积压延迟高；ArrayBlockingQueue有界边界明确可精确控流；SynchronousQueue不缓冲直接转交线程，高峰有拒绝风险；PriorityBlockingQueue保优先级。选型在吞吐、延迟与丢弃间取平衡。

292深挖

CompletableFuture 的 thenCompose 与 thenApply 有何区别？什么时候用？

thenApply返回普通值直接作结果；thenCompose要求返回CompletableFuture，把两个异步操作扁平化串接避免嵌套future。一个操作输出成为下个异步任务输入时用thenCompose，避免future套future。

293深挖

JMM 下 synchronized 的偏向锁为什么如今默认关闭？

偏向锁针对单一长期持有收益有限，且竞争撤销需安全点StopTheWorld，成本高实现复杂。JDK15废弃、JDK17默认禁用，由轻量级锁覆盖低竞争开销。新代码不依赖偏向锁。

294深挖

简述 cache line 伪共享在 LongAdder 中的规避并说明 @Contended？

不同Cell若在同一缓存行，任一核写某Cell使整行Invalid，其余线程连续reload造成false sharing。@sun.misc.Contended给字段加约128字节padding使Cell独占缓存行。LongAdder与CounterCell均用此缓解热点。

295深挖

为什么 volatile 能防止 double-check 单例的半初始化？

实例化三步：分配内存、初始化字段、引用指向对象，编译器可重排为引用先指向未初始化内存。volatile通过StoreStore屏障杜绝该重排，保证引用赋值时对象已构造，配synchronized防半初始化。

296深挖

如何用 AQS 快速实现一个自定义同步器？举例 Semaphore 的写法？

继承AQS覆写tryAcquireShared/tryReleaseShared：把state当可用许可，acquire判断够并减，不够返回非正数入队挂起；release加回许可并唤醒。AQS统一排队、唤醒与中断，用户只定义state语义。

297深挖

CompletableFuture 的 async 多次调用会造成任务膨胀，如何避免？

每用一次thenApplyAsync新增一个任务、可能破坏流水线单任务化，导致任务数量级上升。减少无谓async链式分段，非必要用同步阶段thenApply串在链路，配合受控线程池控制并发与任务总数。

298深挖

线程池核心线程如何处理 keepAliveTime 与预热？

核心线程默认不因空闲回收（除非allowCoreThreadTimeOut(true)）。为预热可在提交前prestartAllCoreThreads/prestartCoreThread把核心线程拉起，避免尖峰首次提交创建线程的延迟。在预启动占用与控制延迟间取舍。

299深挖

从并发角度解释 volatile 与 CAS 组合如何支撑无锁数据结构？

无锁结构用volatile保证可见性，用CAS做原子更新：读走volatile快照，写CAS试改，失败重读重试，并发修改靠重试收敛而非挂起。ABA用版本戳或节点标记解决。本质乐观并发换吞吐，更新需单变量等效原子。

300深挖

如何量化判断并发程序中的锁竞争严重程度？

指标：吞吐TPS、平均与P99延迟、CPU user/sys占比、上下文切换次数、锁等待与自旋统计（jstack、JFR、perf）。若大量线程BLOCKED/WAITING或自旋集中热门锁，吞吐随线程上升不增反降说明竞争重，用JFR圈定再做优化。

301基础

Java 为什么被称为平台无关的跨平台语言？

因为 Java 源代码先编译成字节码（bytecode），运行时不直接依赖具体操作系统，而是由 JVM 解释或 JIT 编译执行。只要目标平台安装了对应版本的 JVM，同一份 class 文件就能运行，从而实现一次编译、处处运行。JVM 本身是平台相关的，但被抽象成统一的运行环境，屏蔽了底层差异。

302基础

JVM 的全称与职责是什么？它和 Java 语言是什么关系？

JVM 全称 Java Virtual Machine（Java 虚拟机），职责是加载字节码并将其转换为当前平台可执行的机器指令，同时为 Java 程序提供运行时内存管理、GC 等服务。JVM 是运行 Java 程序的底层支撑，Java 语言是面向 JVM 的一种编程语言，二者是规范与实现的关系。

303基础

JVM 的内存模型分为哪几个主要区域？

JVM 运行时数据区主要分五块：程序计数器（Program Counter Register）、虚拟机栈（VM Stack）、本地方法栈（Native Method Stack）、堆（Heap）和方法区（Method Area）。其中 Stack 和 PC 是线程私有的，Heap 和方法区是线程共享的。JDK8 之后方法区由 metaspace 实现并迁移到本地内存。

304基础

程序计数器（Program Counter Register）的作用是什么？为什么它是线程私有的？

程序计数器记录当前线程正在执行的字节码指令的地址。每个线程并发执行时都需要独立追踪自己执行到哪一条指令，因此它必须是线程私有的，各线程互不干扰。它也是唯一一个在 JVM 规范中不会抛出 OOM（OutOfMemoryError）的区域。

305基础

Java 虚拟机栈（VM Stack）里存放什么？主要由哪两部分组成？

虚拟机栈是线程私有的，以栈帧（Stack Frame）为单位，栈帧包含局部变量表、操作数栈、动态链接和帧（方法）返回地址。每个方法调用就会创建一个栈帧，方法执行完毕即弹出。局部变量表存基本类型、对象引用和 returnAddress。

306基础

栈和堆在存储内容、生命周期上有什么区别？

栈是线程私有、先进后出，存放局部变量和方法调用栈帧，生命周期跟随线程和方法调用，速度快、不共享；堆是全局共享的，存放对象实例和数组，生命周期由 GC 管理。栈上主要存引用，对象的实际数据通常分配在堆中。

307基础

Java 堆（Heap）的主要作用是什么？它由谁管理？

堆是 JVM 最大的内存区域，用于存放几乎所有对象实例与数组，是线程共享的。堆由垃圾收集器（Garbage Collector）统一管理，是 GC 的主要工作区域，因此也被称为 GC 堆。JDK8 之后堆一般被划分为新生代、老年代等逻辑区域。

308基础

什么是栈溢出（StackOverflowError）与堆内存溢出（OOM）？常见诱因是什么？

栈溢出一般是方法递归调用过深或栈帧过大，导致线程栈空间耗尽，抛出 StackOverflowError；堆 OOM 是堆中对象过多且无法被回收，抛出 java.lang.OutOfMemoryError: Java heap space。二者分别对应栈和堆两种内存资源耗尽。

309基础

对象的创建过程大致分为哪几步？

一般分为五步：类加载检查（确认类已加载/初始化）、在堆中为对象分配内存、初始化零值（将内存置零）、设置对象头（mark word、klass 指针等）、执行构造方法 <init> 初始化实例字段。分配内存常见有指针碰撞和空闲列表两种方式，并配合 TLAB 提高效率。

310基础

对象在内存中的布局（Layout）包含哪几部分？

对象布局主要分三部分：对象头（Header）、实例数据（Instance Data）和对齐填充（Padding）。对象头包含 mark word（存储哈希、锁状态、GC 分代年龄等）与类型指针（klass pointer）。实例数据存放对象实际字段值，对齐填充用于让对象大小按 8 字节对齐。

311基础

什么是 Mark Word？它主要记录哪些信息？

Mark Word 是对象头中占用 8 字节（64 位机器未压缩时）的一个字段，用于存储对象的运行时状态：偏向锁线程 ID、锁状态、对象的 hashCode、GC 分代年龄、是否可偏向等信息。它是实现 synchronized 锁优化和 GC 标记的重要数据结构。

312基础

什么叫 GC Roots？常用的 GC Roots 有哪些？

GC Roots 是可达性分析（reachability）的起点，从这些根出发能引用到的对象视为可达、不会被回收。常用 GC Roots 包括：虚拟机栈中引用的对象、静态变量/常量引用的对象、本地方法栈中 JNI 引用的对象、存活线程、被 synchronized 持有的对象等。

313基础

什么是可达性分析算法？它如何判断对象是否可回收？

可达性分析从 GC Roots 出发，沿引用链向下遍历，凡是能被 GC Roots 直接或间接引用的对象都是可达的。当一个对象不可达时，会在第一次标记后被放入待回收队列，经历 finalize 机会后仍不可达则会被回收。这是主流的判断对象是否存活的算法。

314基础

Java 中的四种引用类型是什么？强度如何排序？

按引用强度从强到弱排列为：强引用（Strong）、软引用（SoftReference）、弱引用（WeakReference）和虚引用（PhantomReference）。强引用只要存在就不会被回收；软引用在内存不足时才回收；弱引用在下次 GC 时即回收；虚引用不能取得对象，仅用于跟踪回收。

315基础

强引用在什么情况下会导致内存泄漏？

强引用会阻止对象被回收。当某个明确不再需要的对象仍被强引用链可达（如静态集合缓存了对象、监听器未移除）时，GC 无法回收它，长期积累就会造成内存泄漏甚至 OOM。因此使用完对象后应主动解除强引用或用弱引用替代。

316基础

软引用和弱引用分别适合什么场景？

软引用适合做内存敏感的缓存，如图片缓存：仅在 JVM 内存不足时回收，可用 in-memory 缓存避免 OOM；弱引用适合做可有可无的关联，如 ThreadLocal 的 Entry、某些缓存框架，对象在下一次 GC 就被回收。两者通常配合 ReferenceQueue 使用以便清理。

317基础

垃圾回收中最基本的算法有哪些？

主要有三种：标记-清除（Mark-Sweep）、复制（Copying）和标记-整理（Mark-Compact）。标记-清除会产生内存碎片；复制按一半空间复制存活对象，无碎片但有空间浪费；标记-整理移动存活对象消除碎片但成本高。实际回收器大多组合使用。

318基础

什么是分代收集理论？为什么要把堆分代？

分代收集基于两个经验假设：绝大多数对象朝生夕灭（弱分代假说），以及熬过越多次 GC 的对象越难被回收（强分代假说）。据此把堆划分为新生代和老年代，新生代用复制算法集中回收短命对象，老年代用标记清除/整理，从而提升整体回收效率。

319基础

什么是 STW（Stop-The-World）？

STW 指 GC 执行时为了让内存状态一致、防止引用链变化，需要暂停所有业务线程，期间用户线程完全停止。任何垃圾收集器都不可避免出现至少短暂的 STW。STW 时间是衡量 GC 性能的重要指标，现代 GC（如 G1、ZGC）的目标就是尽量缩短 STW。

320基础

类加载机制包含哪三个阶段？

类从加载到使用经历三个阶段：加载（Loading）、连接（Linking，含验证、准备、解析）和初始化（Initialization）。加载把字节码读入并生成 Class 对象；连接中准备为静态变量分配默认值；初始化执行 <clinit> 静态初始化块和静态变量赋值。

321基础

什么是双亲委派模型？

当一个类需要被加载时，会先把这个加载请求委派给父类加载器，逐级向上，只有父类无法完成时才由子类加载器自己来加载。默认层次是引导类加载器→扩展/平台类加载器→应用类加载器。这样能保证类的唯一性和核心类库的安全。

322基础

Java 有哪几个内置的类加载器？各自加载什么？

主要有三层：Bootstrap ClassLoader 加载 JVM 核心库（如 rt.jar、JDK9 的 java.base）；Extension/Platform ClassLoader 加载 JDK 扩展库；Application/系统类加载器加载 classpath 下的应用类。JDK9 起扩展加载器改为平台加载器，核心库按模块化拆分。

323基础

什么叫常量池？String 常量存放在哪里？

常量池分两类：类文件常量池（Class file constant pool）和运行时常量池（Runtime Constant Pool）。String 字面量存在字符串常量池（String Table，是运行时常量池的一部分）。JDK7 起字符串常量池从方法区迁移到了 Java 堆中。

324基础

String s = new String("abc") 创建了哪些对象？

这句话会在堆上创建一个 new 出来的 String 对象；同时若字符串常量池中还不存在 abc，会在常量池里创建一个字符串对象。因此一般会创建 1 或 2 个对象。注意 new 出来的对象和常量池中的对象是两个不同实例。

325基础

什么叫方法内联（Method Inlining）？它的好处是什么？

方法内联是 JIT 编译器的一种优化，把被调用小方法的方法体直接内嵌到调用点，省去方法调用的栈帧入栈出栈、参数传递等开销，是对 JVM 性能影响最大的优化之一。内联后还可能进一步触发其他优化如逃逸分析和标量替换。

326基础

常用的 JVM 调优启动参数有哪些（如 -Xms/-Xmx 的含义）？

-Xms 设置堆初始大小，-Xmx 设置堆最大大小，-Xmn 设置新生代大小，-Xss 设置线程栈大小。GC 相关常用 -XX:NewRatio、-XX:SurvivorRatio、-XX:MaxMetaspaceSize（JDK8）、-XX:+UseG1GC 等。生产上通常把 -Xms 与 -Xmx 设为相等以减少扩容抖动。

327基础

JVM 调优的常用命令行工具有哪些？各自作用是什么？

常用工具包括：jps 列出 Java 进程及编号；jstat 查看堆与 GC 统计；jmap 导出堆 dump、查看类加载与堆直方图；jstack 打印线程堆栈（排查死锁）；jcmd 综合诊断命令；visualvm/jconsole 可视化监控。它们统称 JDK 内置诊断工具。

328进阶

虚拟机栈可能抛出哪些异常？分别对应什么情况？

当线程请求的栈深度超过 JVM 允许的最大深度时抛出 StackOverflowError，典型是无限递归；当栈空间无法再申请扩展时抛出 OutOfMemoryError（动态扩展失败）。二者一个是深度超限，一个是容量耗尽扩展失败。

329进阶

方法区（Method Area）存放什么？JDK8 之后发生了什么变化？

方法区存放类型信息（类名、方法字段描述）、常量、静态变量、编译后的代码等。JDK7 及之前方法区实现为永久代（PermGen）位于堆外声明；JDK8 起用元空间（metaspace）替代 PermGen，并改为使用本地内存，不再受堆大小上限约束，且字符串常量与静态变量移到堆中。

330进阶

metaspace 和永久代相比有什么优点？

metaspace 使用本地内存（native memory），默认上限仅受操作系统可用内存制约，避免了永久代引发的 java.lang.OutOfMemoryError: PermGen space 问题。同时永久代是受堆大小影响的特殊区域，移除后简化了堆划分；且字符串常量从永久代移走后，JDK8 中重复字符串能被正常回收，降低泄漏风险。

331进阶

堆中新生代（Young GC 的 Eden 与 Survivor）是如何划分的？比例默认是多少？

新生代划分为一个 Eden 区和两个 Survivor 区（S0、S1）。默认 Eden:Survivor:Survivor = 8:1:1（由 -XX:SurvivorRatio=8 控制）。对象先分配到 Eden，清理时存活对象被复制到当前 Survivor，交换使用两块 Survivor。设计两个 Survivor 是为了避免复制算法浪费一半空间。

332进阶

什么情况的对象会晋升到老年代？

常见情形：对象熬过 15 次 Minor GC（-XX:MaxTenuringThreshold 可调）；大对象直接进入老年代（-XX:PretenureSizeThreshold）；Survivor 中某年龄对象总数占比超过 -XX:TargetSurvivorRatio；或 Survivor 空间无法容纳存活对象时溢出到老年代。

333进阶

什么是 TLAB？它在分配时起什么作用？

TLAB（Thread Local Allocation Buffer，线程本地分配缓冲）是 JVM 为每个线程在 Eden 区预先申请的一块私有分配区域，对象分配优先在 TLAB 内进行，无需对堆进行全局加锁，从而显著提升并发线程下对象分配的吞吐量。TLAB 空间不足时会退化为全局分配或新申请 TLAB。

334进阶

对象分配的两种方式指针碰撞和空闲列表有什么区别？

当堆内存规整、以指针碰撞（Bump the Pointer）方式把空闲内存看成连续空间，移动指针即可分配，简单高效；当经过标记-清除后内存不连续、存在碎片时，用空闲列表（Free List）维护可用内存块，分配时遍历查找合适块。选择哪种取决于 GC 采用的回收算法。

335进阶

为什么需要对象头的 GC 分代年龄？它与晋升有什么关系？

对象头 mark word 中用 4 位记录 GC 分代年龄（最大 15）。对象每熬过一次 Minor GC 且仍存活，年龄就加一。当年龄达到阈值（-XX:MaxTenuringThreshold，默认 15）时会晋升到老年代。年龄字段能帮助 JVM 基于对象存活历史决定何时晋升。

336进阶

简述可达性分析中 finalize 方法的角色及其注意事项。

可达性分析第一次标记不可达后，会判断该对象是否覆盖了 finalize()。若覆盖且未执行过，对象会被放入 finalizer 队列（F-Queue），由低优先级的 Finalizer 线程执行；若在 finalize 中重新建立引用则可复活。自 JDK9 起 finalize 已被标记为废弃，推荐使用 Cleaner/PhantomReference 回收外部资源。

337进阶

标记-清除算法有什么优缺点？它产生的碎片会造成什么影响？

标记-清除先标记存活对象再统一清除未标记对象，实现简单、逻辑清晰，但会产生产生大量不连续的内存碎片，导致后续分配大对象时因找不到连续空间而提前触发 GC。它也是 CMS 等回收器产生内存碎片问题的根源。

338进阶

复制算法是如何解决内存碎片问题的？它的代价是什么？

复制算法把可用内存按容量分成相等两块，只使用其中一块，GC 时把存活对象复制到另一块并清理原空间。它解决了碎片问题且实现简单高效，但代价是需要额外空出一半空间，空间利用率低。因此多用于对象存活率低的新生代。

339进阶

标记-整理算法是如何避免碎片又兼顾空间利用率的？

标记-整理（Mark-Compact）先标记存活对象，再把存活对象向内存一端移动、按序整理，然后清理边界之外的内存。它既消除了内存碎片，又不像复制算法那样牺牲空间，比较适合对象存活率高的老年代，代价是移动对象需要额外开销并涉及引用更新。

340进阶

Serial 和 Parallel 收集器有什么区别？

Serial 是单线程、串行回收的新生代收集器，回收时需 STW 且只有一个 GC 线程，适合客户端或内存较小的场景；Parallel 也叫吞吐量优先收集器，使用多线程并行回收，能充分利用多核 CPU 提高吞吐量，适合对吞吐量要求高的后端批处理场景。二者都搭配 CMS/Serial Old 或 Parallel Old 处理老年代。

341进阶

CMS 收集器的工作大致分为哪几个阶段？

CMS（Concurrent Mark Sweep）以最短停顿为目标，过程分四步：初始标记（initial mark）、并发标记（concurrent mark）、重新标记（remark）、并发清除（concurrent sweep）。只有初始标记和重新标记需要 STW，重标记通常很短，适合对响应时间敏感的应用，但采用标记-清除会产生碎片。

342进阶

CMS 收集器有哪些缺点？为什么逐渐被替代？

CMS 缺点：采用标记-清除会产生内存碎片，可能触发 full GC 前的空间整理；并发标记阶段占用 CPU，与业务线程竞争资源；并发失败时退化为 Serial Old 全停顿回收；无法处理浮动垃圾（并发期间产生的不回收对象）。因此 JDK9 起默认 GC 换成 G1，CMS 逐渐被废弃。

343进阶

G1 收集器的堆结构和回收单位是什么？

G1 把整个堆划分为若干个大小相等的小分区（Region），并动态组成逻辑上的新生代和老年代。它以 Region 为回收单位，维护一个可回收对象多的 Region 优先级列表，回收时按收益选择部分 Region，从而能预测停顿时间（-XX:MaxGCPauseMillis 控制目标），实现可预测的混合回收。

344进阶

G1 为什么能实现较低且可预测的停顿？

因为 G1 把堆拆成很多 Region，回收不必全堆进行，而是通过记录每个 Region 的回收成本与收益，优先回收收益最大、垃圾最多的 Region，并用停顿预测模型估算回收耗时，配合设定停顿目标，把 STW 控制在近乎可预测的范围内。它也采用 SATB 快照降低并发标记与业务线程的竞争。

345进阶

什么是 ZGC？它的最大特点是什么？

ZGC 是面向大堆、以极低停顿（毫秒级，且停顿不随堆大小增长）为目标的高并发垃圾收集器。它通过染色指针（colored pointers）、读屏障（load barrier）和内存多重映射技术，在做对象移动（relocation）时仍能保持与应用线程并发执行，使停顿时间基本恒定在个位数毫秒。

346进阶

JIT 编译器和解释器是什么关系？为什么 HotSpot 采用混合模式？

JIT（Just-In-Time）编译器把热点字节码编译成机器码缓存起来以加速执行，解释器则逐条解释执行。由于解释执行启动快但慢、编译后快但编译有开销，HotSpot 采用解释器与 JIT 混合（mixed mode）：先用解释器快速启动，通过分层编译把热点方法交给 C1/C2 编译，兼顾启动速度与峰值性能。

347进阶

什么是逃逸分析（Escape Analysis）？它能带来哪些优化？

逃逸分析是 JIT 的分析技术，判断对象能否逃逸出方法或线程作用域。基于结果可做三种优化：栈上分配（对象分配在栈上，随方法返回自动销毁）、标量替换（把对象拆成字段直接存在局部变量）、同步消除（去掉无竞争的锁）。这些优化能减少堆分配与 GC 压力。

348进阶

什么是栈上分配和标量替换？

栈上分配指在逃逸分析确认对象不逃逸出方法后，把对象分配到线程栈上，方法结束即释放，无需 GC，避免进入堆。标量替换则进一步把对象拆成多个原始字段（标量）放进局部变量，连栈上对象都不分配。二者都依赖逃逸分析并大幅减少堆中临时对象。

349进阶

常见的 OOM 类型有哪些？

常见类型：java heap space（堆不足）、GC overhead limit exceeded（回收效率极低）、metaspace（元空间不足，JDK8）、unable to create new native thread（线程数超限）、direct buffer memory（直接内存不足）。排查时用 jmap 导出堆 dump 并配合 MAT 分析强引用持有人。

350进阶

内存泄漏和内存溢出（OOM）有什么区别？

内存泄漏（Memory Leak）指不再使用的对象仍被强引用而无法被 GC 回收，内存被悄悄占用、随运行持续增长；内存溢出（OOM）指堆可用空间彻底耗尽而抛出异常。泄漏是溢出的常见诱因之一，但溢出也可能是对象本身过大或分配参数过小导致。排查泄漏通常定位对象数量随时间增长的点。

351进阶

常见的 OOM 排查思路与步骤是什么？

步骤：用 jps 找到进程；用 jstat 观察各区域 GC 与内存使用趋势；用 jmap -dump 导出堆 dump 或 jmap -histo 查看对象直方图；用 MAT/jol 分析线程栈引用链，找出持有对象不释放的根引用；结合代码定位泄漏点。若为 native 内存还需用 pmap、gdb 等排查本地内存。

352进阶

jstat 主要能查看什么信息？常用的输出项有什么含义？

jstat 用于查看 JVM 运行统计，如 -gc 输出各区域容量、已用、GC 次数与耗时，-gcutil 输出各区域使用率百分比，-gcnew/-gcold 分别查看新生代/老年代。通过 S0/S1/E/O 使用率和 M（Metaspace）及 FGC 次数可判断是否需要调优或是否存在全 GC 频繁。

353进阶

jmap 有哪些主要用途？

jmap 常用：-heap 查看堆配置与摘要；-histo[:live] 查看类实例数与占用内存直方图，可快速定位内存大户；-dump:format=b,file=xxx 导出堆 dump 供 MAT 分析。它可以帮助定位 OOM 元凶，如统计对象数量快速增长的大集合类。

354进阶

jstack 用于排查哪些问题？如何定位死锁？

jstack 导出线程堆栈，常用来排查死锁、线程卡死、CPU 飙高、线程阻塞等问题。先 jps 找到 PID 再 jstack <pid>，若存在死锁会输出 Found one Java-level deadlock，定位相互等待的对象锁。也可结合 top -H 找高 CPU 线程号转 16 进制后匹配出业务代码线程。

355进阶

jps 的作用是什么？为什么有时查不到 Java 进程？

jps 列出本机运行的 Java 进程及其主类名和 PID。查不到的情况包括：该 Java 进程与当前用户不一致、环境变量 tmpdir 被改导致 socket 连接失败、进程是 C2 编译的 native 服务或权限不足。它是排查前定位目标进程编号的起点工具。

356进阶

类加载的验证阶段主要验证什么？

验证（Verification）阶段确保字节码安全、符合 JVM 规范，主要做：文件格式验证（魔数、版本）、元数据验证（类继承、方法签名合法性）、字节码验证（指令类型、栈帧一致性，用类型推导）以及符号引用验证。目的是防止恶意或非法的字节码破坏 JVM。

357进阶

类加载的准备阶段做了什么？为什么说它不等同于初始化？

准备阶段为类的静态变量（类变量）分配内存并赋默认零值（如 int=0、引用=null），内存分配在方法区/元空间中。它与初始化不同，此时只是默认值；真正给静态变量赋用户指定值及执行静态代码块发生在初始化阶段。<clinit> 是在初始化才执行的。

358进阶

什么会触发类的初始化？new 关键字、反射、静态方法调用分别如何？

触发主动使用才会初始化：使用 new 实例化、访问或赋值静态字段（非编译期常量）、调用静态方法、反射（Class.forName 默认初始化）、初始化子类先初始化父类、作为 main 入口类。而引用父类静态字段不会初始化子类，编译期常量（static final 常量）也不会触发初始化。

359进阶

为什么需要打破双亲委派？典型场景是什么？

因为有些类只能由特殊加载器来加载，按双亲委派会被父加载器抢走或无法覆盖。典型场景：JDBC SPI，核心 java.sql 由引导类加载器加载，但具体驱动在应用 classpath，需通过 ServiceLoader 由上下文类加载器（TCCL）加载实现类；Tomcat 则用自定义 WebAppClassLoader 实现应用隔离与热部署。

360进阶

什么是线程上下文类加载器（TCCL）？它在 SPI 中扮演什么角色？

TCCL 是每个线程存放的一个类加载器，可由代码设置与恢复。JDBC 等 SPI：引导类加载器加载了 java.sql.DriverManager 接口，但无法看到应用 classpath 中的驱动实现，于是通过 getContextClassLoader() 拿到应用类加载器去加载并注册驱动，从而绕过双亲委派实现接口与实现解耦。

361进阶

String 的 intern() 方法有什么作用？返回值如何判断？

intern() 会去字符串常量池中查找内容相同的字符串：若已存在则返回池中已有引用；若不存在，JDK7/8 会在堆中的常量池记录该字符串的引用（或创建新串）并返回。它常用于减少重复字符串的内存占用。注意公司引入 JDK 版本差异，行为可能不同。

362进阶

字符串常量池什么时候会发生 OOM？

若业务大量产生唯一的字符串并调用 intern() 或因常量传播导致大量字面量进入常量池，字符串常量池需要的内存持续增长。JDK7 后它位于堆中，当内存耗尽时会抛出 java.lang.OutOfMemoryError: Java heap space，而不是 PermGen space。因此需合理使用 intern 或配置堆上限。

363进阶

-XX:MaxGCPauseMillis 对 G1 起什么作用？

它设定 G1 的目标停顿时间（默认 200ms）。G1 的停顿预测模型会根据各 Region 的回收耗时选择回收组合，尽量把单次回收耗时控制在目标内。但它是一个软目标，不一定能绝对保证，且目标设过小可能导致回收不充分、回收频率上升，需配合 -Xmx 等参数综合评估。

364深挖

锁升级过程中 Mark Word 是如何变化的？这体现了 JVM 对锁的哪些优化？

无锁状态 Mark Word 存 hash/age；第一次被单线程获取标记为偏向锁存线程 ID；发生竞争会撤销偏向升级为轻量级锁，Mark Word 存栈中锁记录地址；多线程自旋竞争激烈时膨胀为重量级锁，Mark Word 存 monitor 对象指针。这体现偏向锁、轻量级锁、重量级锁阶梯式升级以平衡竞争开销。

365深挖

对象头的压缩指针（CompressedOops）原理是什么？

默认开启 -XX:+UseCompressedOops 时，64 位 JVM 用 32 位表示对象引用，最多寻址 4G*对齐（对象 8 字节对齐）即 32 GB 堆，从而显著降低对象头中引用所占内存并提升缓存命中。堆超过约 32 GB 时压缩失效，需要整堆超过一定阈值（64GB 左右时 Checked）关闭或无压缩，这也是大堆内存开销增大的原因之一。

366深挖

为什么堆超过 32 GB 后继续增大反而可能降低性能？

在启用 CompressedOops 时堆越大、压缩引用相对越不划算，还伴随单次 GC 停顿增长、缓存命中率下降以及跨代指针处理开销增加。因此并非堆越大越好，ZGC 通过染指针等解决引用宽度问题，但要权衡 CPU 与标志位改动的成本，过大堆需结合 GC 与本地内存综合考量。

367深挖

为什么 JVM 实际可分配的内存可能远小于 -Xmx 设定的值？哪些区域不占用 -Xmx？

-Xmx 只约束 Java 堆（heap + 一些内部堆结构），不包含 metaspace、线程栈、直接内存（DirectByteBuffer）以及 JIT、GC 结构等本地内存。这些 Native 部分可能达到堆的若干倍。若未显式配置 -XX:MaxMetaspaceSize、线程数过多或使用大量 NIO，就会出现本机内存耗尽而堆未用满的情况。

368深挖

G1 的 Mixed GC 与 Full GC 有什么区别？

G1 的 Young GC 只回收新生代 Region；Mixed GC 同时回收部分高收益的老年代 Region，仍受 MaxGCPauseMillis 约束；Full GC 是并发失败（Concurrent Mode Failure）或分配失败时退化为用 Serial Old 全堆 STW 回收，停顿长，优化目标是尽量避免。

369深挖

G1 的 SATB（Snapshot At The Beginning）与 CMS 的增量更新有何区别及取舍？

CMS 用增量更新（Incremental Update）追踪浮动对象，需重新标记时扫描引用；G1 的 SATB 在并发标记开始时拍一张堆对象图快照，标记期间新产生的引用记录到缓冲区，重标记时处理，牺牲一定空间换取更低的并发标记与业务线程交互开销，且能降低浮动的对错杀漏标风险。二者在吞吐量与停顿上各有取舍。

370深挖

ZGC 如何做到几乎为零的停顿？上色指针/内存屏障如何协同？

ZGC 用染色指针（在对象指针高位存放 Marked、Moved 等状态位）配合读屏障（load barrier）与多重映射：访问被移动对象时读屏障能立即重定向到新地址，始终维护正确引用；移动（relocation）与其前级标记全程与应用线程并发，只有极短的初始标记/一致性检查需要 STW，因此停顿稳定在毫秒级且与堆大小无关。

371深挖

经典 CMS 为什么在并发阶段无法避免浮动垃圾？

CMS 并发标记/清除期间业务线程仍在运行，可能产生新对象并把某些已处理对象重新引用，这些在并发标志结束后才出现或被改引用的对象无法被本次回收覆盖，称为浮动垃圾（floating garbage），只能留待下一次 GC。为保证并发清除期间有内存可用，CMS 需预留空间，若空间不足则触发并发失败退化为全停顿的 Serial Old。

372深挖

如何理解分代假设在 G1/ZGC 中的弱化？

G1 基于 Region 仍保留分代（新生代/老年代是逻辑上的），通过回收收益排序提高收益；ZGC 则完全不把分代作为主要手段，针对大堆和低停顿用并发的染色指针方案，实测更关注存量对象分布而不是严格分代。分代假说仍是传统调优的重要经验，但新一代收集器通过并发标记与分区调度淡化了对固定分区的依赖。

373深挖

如何判断一次 Full GC 是因为 metaspace 不足而不是堆不足？

观察 jstat -gcutil 的 M 列接近 100% 或持续增长，或异常为 java.lang.OutOfMemoryError: Metaspace。常见诱因是大量动态生成类（CGLIB、反射、Groovy、热部署）。可用 -XX:MaxMetaspaceSize 设上限，并用 jcmd GC.class_stats 或导出 dump 定位类加载器泄漏。

374深挖

CGLIB/动态代理为什么会造成 metaspace 增长与泄漏，如何控制？

CGLIB 和大量反射代理会在运行期生成新的 class，强制加载这些类会不断占用 metaspace。若类加载器（如非静态内部类持有 classloader 引用）未及时卸载，类无法回收导致 metaspace 持续增长直至 OOM。对策：升级 JDK 用内置 InvocationHandler 搭配 -XX:MaxMetaspaceSize 限制上限并定位类加载器泄漏点。

375深挖

为什么说 GC Roots 遍历常是 STW 的关键瓶颈之一？

可达性分析要对线程栈、全局对象等并行扫描，且必须保证线程不修改引用，否则结果不稳定。现代收集器用并发标记（如 G1 的 SATB、CMS 的并发标记）把大范围遍历移出停顿，但初始标记仍要枚举根集合，根扫描本身需 STW。引入并行根扫描（Parallel Roots Scanning）与彩色指针技术就是在压缩这段关键停顿。

376深挖

如何用 mat 分析 heap dump 定位内存泄漏？关键视图有哪些？

mat 打开 -dump 生成的 hprof 后用 Histogram 看大对象类别，用 Dominator Tree 找出最大支配者；对疑似泄漏对象用 Path To GC Roots（exclude weak reference）追踪可达根，找出持强引用的静态集合或长生命周期对象；对比多次 dump 可知增长点。还可结合 Leak Suspects 自动报告可疑泄漏。

377深挖

jcmd 相比 jmap/jstack 有哪些更强的诊断能力？

jcmd 功能更全，常用子命令：GC.class_histogram、GC.heap_dump、Thread.print、VM.flags、VM.system_properties、GC.run 等，还能开启 JFR（VM 相关命令）。相比 jmap/jstack，能一站式完成堆直方图、线程栈、JVM flags 等诊断查询。

378深挖

JFR（Java Flight Recorder）在 JVM 调优中的作用是什么？

JFR 是 JVM 内置的低开销性能分析器，能持续记录线程执行、GC、分配热点、方法调用采样等事件，改写之后通过 JDK Mission Control（JMC）分析。它可用于事后火山排查：enabled with -XX:StartFlightRecording 或运行时 jcmd 开启，对定位性能瓶颈与最根本的分配热点很有效。

379深挖

什么是方法的内联失败（放弃内联）？它与接口调用/多态有什么关系？

当被内联的方法太大、调用点类型不一致或出现动态分派（虚拟方法），若无法确定唯一目标就难以内联。JIT 通过 type profile 在统计上判断热点单一实现后仍可能内联（部分 vtable 优化），否则回退为虚拟调用，内联失败会增大调用开销并影响其他优化（如逃逸分析的场景）。这是 profiling JIT 的关键取舍。

380深挖

为什么说双重检查锁单例要加 volatile 才能保证安全发布？

对象创建分三步：分配内存、初始化字段、把引用指向对象，JVM 会重排指令，可能先返回引用再初始化。双重检查下第二个线程可能读到半初始化对象。volatile 通过内存屏障禁止该重排，并保证多线程可见性，确保发布后再初始化完成，避免使用不完整实例。JDK 也可配合 final 字段的部分可见性优化。

381深挖

ThreadLocal 为什么会造成内存泄漏？与弱引用 Entry 有什么关系？

ThreadLocalMap 的 key 对 ThreadLocal 是弱引用，value 是强引用。ThreadLocal 失去强引用后 key 被回收，但 value 仍被线程强引且 Entry 滞留 map 中，若线程存活且未调用 set/get/remove 清空失效条目就会累积泄漏。因此使用后应显式 remove() 清理。

382深挖

线程池中的线程如何造成堆内存泄漏？如何规避？

线程池线程存活时间长，若在线程内隐式绑定长生命周期对象（如 ThreadLocal value 未被清理、静态大集合被引用），这些对象即使业务不再需要也无法回收，随任务执行持续增长直至 OOM。规避：任务结束后显式清理 ThreadLocal（remove）、控制对象引用生命周期、分析堆找出持有者。

383深挖

为什么说字符串常量池在 JDK7 移动后 intern 不再一定带来回收可靠性，需要注意？

JDK7 后字符串常量池位于堆，若对象不在池中则 intern 时会在池中存放堆对象的引用而非对象拷贝，因此随意 intern 会让大量字符串常驻常量池无法被 Minor GC 及时回收，反而可能撑大堆。生产应避免滥用 intern，仅在确知字符串有限且去重收益大时使用。

384深挖

-XX:+UseCompressedClassPointers 与 UseCompressedOops 分别压缩什么？

UseCompressedOops 压缩对象引用（指针）；UseCompressedClassPointers 压缩对象头中指向 Klass 的类型指针（Class Pointer），使对象头可降到 12 字节。两者默认开启且与 UseCompressedOops 有联动，但基地址为 32GB 对齐。关闭任一压缩会增大对象头开销，影响堆内存利用与缓存命中。

385深挖

JIT 编译过程中 profiling 与分层编译（C1/C2 Tiered）如何协同？

HotSpot 默认开启分层编译：先用解释器采集调用次数、类型分布等 profile，C1 编译器快速生成带 profile 的中等优化代码，熟统计数据成熟后再由 C2（优化编译器）生成极致优化版本。这一机制使 JVM 能根据运行期信息做类型推断、内联与逃逸分析等，兼顾启动速度与稳态性能。

386深挖

什么情况下会出现 GC overhead limit exceeded？压测中如何定位？

当 GC 回收效率极低、回收几乎不释放内存且回收耗时占总时间过高（默认超过 98% 而回收不到 2% 堆）时抛出该异常。通常意味着堆被占用尽、对象几乎全部存活或存在大量无效回收。方案：缩小对象、增大 -Xmx、分析堆找出大量存活对象、排查是否长时间持有或缓存未清理，同时配合 dump 定位根。

387深挖

JVM 直接内存（Direct Memory）什么时候会 OOM？为什么 jmap 不一定显示？

DirectByteBuffer 通过 Unsafe 分配在 JVM 堆外的本地内存，受 -XX:MaxDirectMemorySize（默认等于 Xmx）限制，NIO/Netty 缓冲未及时释放就可能 OOM。jmap 只统计 Java 堆，直接内存不会显示，需用 pmap 或 NMT 观察 native 内存和进程 RSS，DirectByteBuffer 靠 Cleaner 回收。

388深挖

在容器（Docker/云）环境下 JVM 参数有哪些注意点与坑？

老版本 JVM 默认按宿主机 CPU/内存计算默认堆与线程数，容器内易 OOM 或回收异常，应显式设 -Xmx、-Xms 与 -XX:ParallelGCThreads。JDK8u191+ 默认开启 UseContainerSupport，可配合 -XX:MaxRAMPercentage 按容器可用内存比例设置；同时需给 native 与直接内存预留足够余量。

389深挖

如何用 NMT（Native Memory Tracking）排查本地内存泄漏？

启动加 -XX:NativeMemoryTracking=summary（或 detail），用 jcmd <pid> VM.native_memory summary 查看 malloc 总量及 Java heap、class、thread、code cache、GC、internal 等各分类占比。多次采样对比可发现持续增长的 native 类别并定位子系统；detail 开销大，生产谨慎使用。

390深挖

调优选择 Serial 还是 G1/ZGC 的核心判断标准是什么？

标准是应用对停顿/吞吐的敏感度和堆规模：小堆单机低延迟可选择的是 Serial；传统吞吐大量用 Parallel；需停顿控制在秒级以内且堆中等用 G1；而 ZGC 面向超大堆且要求极低停顿（如在线交易）时更合适。同时关注 CPU 资源、分配速率与是否允许并发回收的 CPU 损耗，不能只看标注的停顿目标。

Spring IOC 是什么？DI 在其中扮演什么角色？

IOC（控制反转）将对象创建与依赖管理交给容器，由容器维护 Bean 生命周期。DI（依赖注入）是其实现方式，容器创建对象时通过构造器或 setter 自动注入依赖，从而降低耦合。

397进阶

Spring Bean 的生命周期有哪些主要阶段？

包括实例化 Bean、属性填充（依赖注入）、Aware 回调、BeanPostProcessor 前置处理、初始化（InitializingBean/init-method）、BeanPostProcessor 后置处理、使用、销毁，整体由容器统一管理。

398进阶

Spring Bean 默认作用域是什么？还有哪些常用作用域？

默认是 singleton 单例，容器中同一名称只一份实例；另有 prototype 原型（每次获取新建）、request/session/application 等 Web 作用域。单例省资源但与有状态对象冲突。

399进阶

@Autowired 和 @Resource 的区别是什么？

@Autowired 是 Spring 提供，默认按类型注入，搭配 @Qualifier 按名称，required 可设必填；@Resource 是 JSR-250 规范，默认按名称注入，找不到再按类型。多实现时 @Autowired 常需用 @Qualifier 区分。

400进阶

Spring AOP 的实现原理是什么？JDK 动态代理和 CGLIB 有何区别？

AOP 基于代理实现切面。目标类实现了接口时默认用 JDK dynamic proxy（基于 InvocationHandler）；未实现接口则用 CGLIB 生成子类代理。Spring Boot 2.x 起默认使用 CGLIB（proxyTargetClass=true）。

401进阶

@Component、@Service、@Controller（或 @RestController）三者区别？

三者功能上等价，都是把类注册为 Spring Bean，作用相同。区别在语义分层：@Service 标注业务层、@Controller/@RestController 标注控制层、@Component 是通用组件，按分层语义选用更清晰。

402进阶

@RestController 和 @Controller 有什么不同？

@RestController 是 @Controller 加 @ResponseBody 的组合，返回值直接序列化为 JSON/文本写入响应体，适合 RESTful 接口；@Controller 返回视图名配合模板引擎，输出 JSON 时需额外加 @ResponseBody。

spring-boot-starter-jdbc 或 JPA starter 如何与数据库集成？

404进阶

如何通过配置文件区分多环境，如 dev/prod？

用 application-{profile}.yml 定义各环境配置，通过 spring.profiles.active 指定激活环境。如 application-dev.yml、application-prod.yml，启动时设置 profile 即可切换数据库、日志等配置实现隔离。

405深挖

什么时候会触发循环依赖？为什么构造器注入无法解决？

单例 Bean 相互依赖时会产生循环依赖，Spring 通过三级缓存提前暴露对象解决 setter 注入的情况。构造器注入因创建时就要完成注入、无法提前暴露半成品对象，所以解决不了，应尽量避免构造器循环依赖。

406深挖

Bean 初始化过程中三级缓存分别缓存什么？

一级缓存 singletonObjects 存已创建完成的 Bean；二级缓存 earlySingletonObjects 存提前暴露的早期对象；三级缓存 singletonFactories 存对象工厂。循环依赖时先从三级缓存取工厂生成早期引用再入二级缓存完成注入。

407深挖

Spring 事务注解 @Transactional 什么时候会失效？

@Transactional 基于代理生效，常见失效原因：private 方法无法代理、同类内部调用（this 调用）绕过代理、异常被捕获未抛出、默认仅回滚 RuntimeException 而异常类型不匹配、未开启代理等。

Spring Boot 启动流程的简化核心步骤有哪些？

bootstrap.yml 和 application.yml 有什么不同？

bootstrap.yml 优先级更高、加载更早，主要用于从配置中心（如 Nacos/Spring Cloud Config）拉取配置并初始化外部化环境；application.yml 是应用自身配置。没有配置中心时通常只用 application.yml。

自定义一个 Starter 需要包含哪些核心元素？

411基础

介绍下 SQL 语句可以分为哪几大类，各自作用是什么？

SQL 分四类：DDL 定义表结构（create/alter/drop），DML 操纵数据（insert/update/delete），DQL 查询（select），DCL 控制权限（grant/revoke）。先答四大类再各举一例更能体现基础扎实。

412基础

DDL 和 DML 的区别是什么？

DDL 操作的是表、库等对象的结构且隐式提交事务，MySQL 会隐式 commit，不能 rollback 回滚；DML 操作的是表中的行数据，隶属于事务，可回滚。这是核心区别：一个动结构不参与事务，一个动数据参与事务。

413基础

WHERE 和 HAVING 的区别是什么？

WHERE 在分组之前过滤行，不能使用聚合函数作为条件；HAVING 在 group by 分组之后过滤，专门用于聚合结果的条件筛选。执行顺序上先 WHERE 过滤再 GROUP BY 再 HAVING，性能上尽量把能过滤的条件放到 WHERE 中。

414基础

SQL 中 IN、EXISTS 和 JOIN 各自的适用场景有哪些？

IN 适合子查询结果集较小的情况，EXISTS 更适合外层表记录少而子查询内表很大的场景（命中走索引时性能好），JOIN 则把两张表按关联条件连接。三者结果可等价，但引擎优化器与实际数据分布不同性能各异，需结合执行计划判断。

415基础

UNION 和 UNION ALL 的区别是什么？

UNION 会去重并做排序，UNION ALL 直接合并所有行不去重。因此 UNION 性能相对更差，但结果唯一；若确认数据无重复，应优先使用 UNION ALL 以提升性能并减少临时表开销。

416基础

常用的 MySQL 存储引擎有哪些？

最常用的是 InnoDB 和 MyISAM，还有 MEMORY（内存表）与归档引擎等。InnoDB 是 MySQL 5.5 以后的默认引擎，支持事务、外键和行级锁，是生产环境的首选；MyISAM 只支持表级锁、不支持事务，已趋于淘汰。

417基础

InnoDB 和 MyISAM 的主要区别是什么？

InnoDB 支持事务、外键与行级锁，适合高并发写；MyISAM 仅支持表级锁、无事务、支持全文索引且数据文件更紧凑。另外 MyISAM 统计行数较快是因为 count(*) 直接读计数，InnoDB 需扫描，但并发与安全性 InnoDB 全面占优。

418基础

主键和唯一索引的区别是什么？

主键唯一且非空，一张表只能有一个，InnoDB 中常作为聚簇索引组织数据；唯一索引也保证唯一性但允许一个 NULL 值，一张表可有多个。二者本质都是唯一性约束，但主键还承担着数据物理组织的作用。

419基础

索引的作用是什么？使用索引有哪些代价？

索引能极大加快查询速度，本质是以空间换时间，通过减少扫描数据行数来加速检索。代价是占用额外的磁盘空间，并且增删改时需同步维护索引导致写入变慢。所以索引不是越多越好，要针对高频查询建立。

420基础

什么是聚集索引（聚簇索引）？

聚集索引（clustered index）是指索引的叶子节点直接存储整行数据，数据和索引存储在一起。InnoDB 的主键索引就是聚簇索引。因为一行数据只有一个物理位置，所以一张表只能有一个聚簇索引。

421基础

什么是回表查询？

回表是指先通过二级索引（非聚簇索引）找到主键值，再根据主键到聚簇索引的 B+Tree 中去查完整行数据的过程。因为二级索引叶子节点只存主键，不含整行，所以需要二次查找，回表会增加一次磁盘 IO。

422基础

MySQL 的四条底层日志分别是什么？

四条关键日志：undo log 用于回滚与 MVCC，redo log 保证崩溃恢复，binlog 用于主从复制与数据恢复，relay log 是从库暂存主库 binlog 的中继日志。

423基础

事务的四大特性 ACID 是什么？

ACID 指原子性（全成功或全回滚，靠 undo log）、一致性（数据一致）、隔离性（互不干扰，靠锁与 MVCC）、持久性（靠 redo log）。按此对应回答更显深度。

424基础

MySQL 默认的事务隔离级别是什么？

MySQL InnoDB 默认隔离级别是 REPEATABLE READ（可重复读）。注意这与 Oracle 默认的 READ COMMITTED 不同。得益于 MVCC 和临键锁，RR 级别能同时避免脏读、不可重复读和幻读的大部分场景。

425基础

什么是脏读、不可重复读、幻读？

脏读是读到另一个未提交事务修改的数据；不可重复读是在同一事务内两次读取同一行却得到不同结果（因他事务提交了 update）；幻读则是指同一事务内两次查询同一范围却多出了新插入的行（phantom row）。

426基础

乐观锁和悲观锁分别是什么？使用场景有何不同？

悲观锁认为并发冲突经常发生，访问前先加锁（如 select ... for update，数据库行锁）；乐观锁认为冲突少，提交时用 version 或时间戳校验是否被修改，冲突则重试。读多写少适合乐观锁，写冲突频繁适合悲观锁。

427基础

如何查看一条 SQL 是否使用了索引？

用 EXPLAIN + SQL 查看执行计划，重点看 type 是否达到 range/ref/eq_ref/const，是否命中预期索引 key，rows 预估扫描行数是否合理。type 为 ALL 说明全表扫描，需加索引优化。

428基础

一道求表中姓名为张三记录的 SQL，写出其基本 SELECT 语句形如。

基本形式为 SELECT 列 FROM 表名 WHERE 姓名 = '张三'。若要优化可在姓名列建立索引以加速 where 过滤，并通过 EXPLAIN 确认命中索引。这是最基础的 DQL 写法，先明确要查的列再写过滤条件。

429基础

简述一条 UPDATE 语句的执行流程，涉及哪些日志？

先定位要更新的行，在 Buffer Pool 中修改，旧值写入 undo log 支持回滚与 MVCC，同时写 redo log 保证崩溃恢复，提交时再写 binlog 用于复制。一条 update 会同时涉及 undo、redo、binlog 三方日志。

430进阶

InnoDB 为什么选用 B+Tree 作为索引结构而不是红黑树或哈希？

B+Tree 是多叉树，树高更低，千万级数据一般只有三层，IO 次数少；叶子节点直接存放数据并形成有序链表，非常适合范围查询与排序；B+Tree 非叶子节点只存索引键，扇出更大。而红黑树是二叉树树高过高，哈希树不支持范围查询。

431进阶

联合索引的最左前缀原则是什么？

最左前缀是指联合索引 (a,b,c) 在查询时必须从最左边的列开始连续匹配才能使用该索引。例如 where a=? 可用，where a=? and b=? 可用，where b=? 单独无法用该索引。优化器会尽量利用该原则决定索引的列参与顺序。

432进阶

什么是覆盖索引？为什么它能避免回表？

覆盖索引（covering index）指查询所需的所有列都存在于某个二级索引中，无需再回表查询聚簇索引。因为二级索引 B+Tree 的叶子节点已包含这些列，直接读取即可，从而省去一次回表 IO，是高并发查询的常用优化手段。

433进阶

列举几种会导致索引失效的常见场景？

常见的有：对索引列使用函数或隐式类型转换、like 以通配符开头（%abc）、在索引列上进行运算、OR 连接未全部覆盖索引列、以及 left join 的 on 与 where 条件类型不一致等。这些都会使优化器放弃走索引而回退到全表扫描。

434进阶

like 查询 '%abc' 为什么用不上索引？

B+Tree 索引是按索引值从左到右有序排列的，like '%abc' 的前缀是不确定的通配符，无法利用 B+Tree 的二分定位特性定位起点，只能全量遍历，所以优化器放弃使用该索引。而 like 'abc%' 前缀确定，可正常走索引范围扫描。

435进阶

MVCC 的全称和核心思想是什么？

MVCC 即 Multi-Version Concurrency Control（多版本并发控制）。核心是为每行维护多个版本（配 undo log 保留旧版本），读写按版本链读取符合快照的数据，实现读不加锁、读写互不阻塞，提升并发性能。

436进阶

MVCC 中 ReadView 的作用是什么？

ReadView 是 MVCC 判断某版本对当前事务是否可见的快照，记录活跃事务列表 m_ids、最小活跃事务 id、分配到的最大事务 id 等。比较被判定版本的事务 id 是否属活跃事务，决定读当前版本还是沿版本链向上找旧版本。

437进阶

redo log 和 binlog 的区别是什么？

redo log 是 InnoDB 层物理日志，记录页的物理变更，用于崩溃恢复，循环写；binlog 是 Server 层逻辑日志，记录 SQL 或行级逻辑操作，用于主从复制与时间点恢复，追加写。二者层级、内容与用途不同。

438进阶

undo log 的作用有哪些？

undo log 主要有两个作用：一是实现事务回滚，保存被修改行的旧版本以便 rollback 时恢复；二是配合 MVCC 构建版本链，为读操作提供历史版本的可见性。它记录的是逻辑上的反操作，删改会留有旧值记录。

439进阶

两阶段提交（2PC）在 MySQL 中如何保证 redo 与 binlog 一致？

提交时先写 redo log 处于 prepare，再写 binlog，最后把 redo 置 commit。写 binlog 前崩溃则回滚，binlog 写完则按 binlog 提交，从而保证 redo 与 binlog 一致，避免主从不一致。

440进阶

MySQL 有哪几种锁类型？请分类说明。

按粒度分有表级锁（元数据锁、自增锁）和行级锁（record lock）；按模式分有共享锁（S 锁）和排他锁（X 锁）；还有针对间隙的 gap lock 与 next-key lock。意向锁（IS/IX）用于协调表锁与行锁的兼容。

441进阶

什么是记录锁（record lock）、间隙锁（gap lock）和临键锁（next-key lock）？

record lock 锁住索引上一行；gap lock 锁住索引值间间隙以阻止插入、防幻读；next-key lock 是二者组合，锁住记录及前方区间。RR 级别 InnoDB 默认用 next-key lock 解决幻读。

442进阶

在 REPEATABLE READ 下 MySQL 如何解决幻读？

通过 next-key lock 与 MVCC 结合：当前读（select ... for update、update）时用 next-key lock 锁定范围并阻止间隙插入；快照读时靠 MVCC 读取一致快照，使两次查询看不到新插入的行，从而解决幻读。

443进阶

普通查询 select 与当前读 select ... for update 在加锁上的差别？

普通 select 在 MVCC 下是快照读（非锁定读，即不加锁的一致性读），直接读版本链而不加锁；select ... for update 与 update/delete 是当前读，读取最新数据并加排他锁，直到事务结束才释放，用于防止并发写冲突。

444进阶

什么情况会发生死锁？如何处理？

死锁发生在多个事务以不同顺序持有并相互等待对方持有的锁时，形成循环等待。可通过调整加锁顺序、缩小事务范围、使用更小粒度锁来避免；MySQL 会用死锁检测自动回滚代价较小的一个事务，靠 InnoDB 的 wait-for graph 机制解决。

445进阶

什么是主从复制？主要解决什么问题？

主从复制指把主库（master）的 binlog 传输给从库（slave），从库通过 relay log 重放实现数据一致。主要用于读写分离（读分摊到从库减轻主库压力）、容灾备份以及在线数据迁移。复制默认是异步或半同步的。

446进阶

什么是读写分离？实现时要注意哪些一致性问题？

读写分离是指主库承担写操作，从库承担读操作以提升吞吐。由于复制有延迟，可能出现刚写入主库的数据在从库读不到，即读写不一致。可通过半同步复制、强制关键读走主库或短时缓存等待来缓解读延迟带来的数据不一致。

447进阶

水平拆分和垂直拆分分别是什么？

垂直拆分是按业务或字段将一张宽表拆成多张相关的表，或按模块分库，例如把订单的基本信息与详情拆开；水平拆分是把同一张表的数据按分片键（如 user_id、订单 id 取模）分散到多台库表，即分库分表，解决单表数据量过大的问题。

448进阶

分库分表后常见的分布式难题有哪些？

主要有三类：全局唯一主键不易生成（可用雪花算法、Redis 发号器）；跨库分页与跨库 join 难以处理（常需应用层组装或冗余数据）；分布式事务无法用本地事务保证，需要 XA、TCC 或最终一致性方案（如基于消息的可靠最终一致）。

449进阶

什么是慢查询？如何定位与分析？

慢查询指执行时间超过设定阈值的 SQL，可通过开启慢查询日志（slow_query_log）记录。定位到具体 SQL 后用 EXPLAIN 分析执行计划，检查是否全表扫描、索引未命中、扫描行数过大或锁等待过长，再针对性优化 SQL 或索引。

450进阶

EXPLAIN 结果中的 type 字段有哪些常见取值？

按性能从好到差为 system、const、eq_ref、ref、range、index、ALL。ALL 是全表扫描最差，index 是全索引扫描略好，range 是范围扫描，ref 是非唯一索引等值，eq_ref 是唯一关联，const 是主键等值最优。

451进阶

为什么 InnoDB 中 count(*) 比 count(1) 并不慢，企业常如何优化大表计数？

InnoDB 走聚簇索引扫描，count(*) 与 count(1) 都自动选最小索引统计，差异可忽略；影响性能的是全表行数本身。大数据量下往往用缓存计数（如 Redis）或单独计数表配合事务维护，并在允许时有延迟容忍度。

452进阶

order by 排序时如何尽量使用索引避免 filesort？

当 order by 的字段与查询条件形成了符合最左前缀的联合索引，优化器可直接按 B+Tree 有序性返回结果，避免 filesort。反之若无法利用索引排序，就会产生外部文件排序。因此让排序字段尽量参与联合索引可提升排序性能。

453进阶

JOIN 查询大表时通常如何优化性能？

核心是让被驱动表（内层循环表）的连接字段有索引，避免对每行都全表扫描；尽量用小表驱动大表，减少关联扫描次数；用 EXPLAIN 观察驱动顺序；必要时用派生表子查询先缩窄数据量，或用冗余字段、反规范化避免 join。

454进阶

什么是外键约束？生产环境为什么不推荐使用外键？

外键用于保证表与表之间的引用完整性，能约束父子表的插入删除。但外键在更新删除时会带来额外检查和级联，降低写入性能并可能引发锁竞争与死锁，且分库分表后外键失效。因此高并发场景常用应用层逻辑替代外键。

455进阶

什么是深分页问题？如何优化 limit 大偏移？

深分页指 offset 很大时，MySQL 仍会扫描并丢弃前 offset 行，性能低下。可改为利用上一页最后一条记录的主键或唯一键做条件定位，即 where id > lastId limit N 的游标分页；或用延迟关联，只先取主键再回表取全数据。

456深挖

InnoDB 的 B+Tree 索引为什么一个页一般是 16KB？三层能存多少数据？

InnoDB 默认 page 大小为 16KB。非叶子节点一个记录约占十几字节，一个页可存约千个键，若两层非叶子约可容纳百万记录，三层则可支撑千万到上亿行。三层结构意味着定位一行数据最多三次磁盘 IO，性能稳定可控。

457深挖

聚簇索引为什么会尽量选择自增整型作为主键？

自增主键在新插入时记录追加到 B+Tree 末尾，页分裂较少且叶子顺序紧凑；而随机字符串主键会导致页频繁分裂、产生碎片并引起大量随机 IO。因此 InnoDB 推荐使用自增整型聚簇键以提升插入性能并减少页重构。

458深挖

当表没有主键时 InnoDB 会如何选择聚簇索引？

InnoDB 会优先挑选一个非空唯一索引作为聚簇索引；若不存在唯一索引，则隐式生成一个 6 字节的 rowid 作为聚簇键组织数据。这会影响回表与索引效率，所以建议显式定义主键以决定数据的物理组织方式。

459深挖

MVCC 中事务可见性的具体判定逻辑是怎样的？

ReadView 记录生成时的活跃事务 m_ids。判定某版本可见：若版本事务 id 小于 m_ids 最小值则已提交可见；若大于等于当前事务控制点则不可见；若在活跃列表内也不可见，否则可见。不可见时沿 undo 版本链向前找更旧版本继续判定。

460深挖

RC 与 RR 隔离级别下 ReadView 的生成时机有何不同？

在 READ COMMITTED（RC）下，每次快照读都生成新 ReadView，能看到他事务已提交数据，出现不可重复读；在 RR 下只在第一次快照读生成并复用同一个 ReadView，保证整个事务读到一致快照，避免不可重复读。

461深挖

redo log 的刷盘策略（flush）与 WAL 机制如何保证持久性？

WAL 指先写 redo log 再落数据页。innodb_flush_log_at_trx_commit 控制刷盘：0 每秒刷一次、1 每次提交 fsync（最安全）、2 只写操作系统缓存。设为 1 崩溃后数据不丢，但性能较低。

462深挖

Buffer Pool 是什么？LRU 淘汰在 MySQL 中如何处理热冷数据？

Buffer Pool 是 InnoDB 的内存缓冲池，缓存数据页与索引页以减少磁盘 IO。它使用改进的 LRU 算法，将链表分为热（young）区与冷（old）区，新读入的页先进入冷区，避免全表扫描把热数据挤出，从而提升缓冲命中率。

463深挖

什么是自适应哈希索引（AHI）？

自适应哈希索引是 InnoDB 根据热点查询自动建立的哈希索引，建立在 B+Tree 之上的缓存层，用于加速等值查询。它由数据库自动维护，无需 DBA 手动创建，但只对等值查询有效，且占用 Buffer Pool 内存。

464深挖

为什么联合索引在 order by、group by 上也很有用？

B+Tree 叶子节点按索引列有序存储，若查询条件与 order by/group by 的列共同满足最左前缀，数据天然有序，可直接按序输出或分组，避免 filesort 与临时表（Using temporary），大幅减少排序分组开销。

465深挖

覆盖索引 + 最左前缀 如何配合解决深分页性能问题？

先用覆盖索引只检索主键实现快速定位偏移，再通过主键 IN 或延迟关联回表取得完整行，能避免深分页时对数据的无效回表扫描。因为只扫描索引页而非数据页，IO 减到最小，是分页性能优化的常用方案。

466深挖

MySQL 的 binlog 有几种格式？各自特点？

有 statement（记录 SQL 语句，日志量小但非确定性函数可能复制不一致）、row（记录行变更，最精确且支持闪回，但日志量大）和 mixed（语句与行混合，由 MySQL 自动选择）。生产上为数据一致性较常用 row，配合 RBR 完成精确复制。

467深挖

半同步复制与异步复制的区别及半同步的潜在问题？

异步复制中主库提交后就返回，不等待从库确认，延迟可能丢数据；半同步复制要求至少一个从库收到 binlog 并 ack 后才向客户端提交成功，降低丢失风险。但半同步会因等待 ack 增加主库提交延迟，且从库数量多时整体吞吐受影响。

468深挖

分布式事务中最终一致性常用方案有哪些？简要说明 TCC。

常用有 XA 强一致、TCC、SAGA、本地消息表加 MQ 的可靠最终一致等。TCC 把一次业务拆为 Try（预留资源）、Confirm（确认执行）、Cancel（补偿回滚）三个阶段，通过两阶段协调和补偿来保证分布式环境下最终一致，适合对一致性敏感的业务。

469深挖

分库分表后如何做全局唯一主键？

可使用 Snowflake 雪花算法生成基于时间戳、机器 id 与序号的 64 位 id；或使用 Redis 的 INCR 发号、数据库号段模式预取一批号区间；也可用全局 UUID 但无序不宜做索引。生产常用雪花算法兼顾唯一性与趋势递增，利于分片与索引。

470深挖

MySQL 如何解决自增主键冲突（自增锁与批量插入）？

InnoDB 的自增锁是表级锁，插入时分配自增值。innodb_autoinc_lock_mode 控制加锁粒度，批量插入仍可能持表级锁影响并发，故高并发场景常用雪花 id 等分布式 id 替代自增主键。

471深挖

什么是 Using index condition（索引条件下推，ICP）？

ICP 是 MySQL 的优化特性，指将 where 中能否在二级索引上过滤的条件下推到存储引擎层执行，在读取索引时先过滤再回表，减少回表次数。对联合索引前缀过滤之外的非索引列条件尤其有效，能显著减少数据页读取。

472深挖

什么情况下优化器会放弃使用索引而选择全表扫描？

当使用索引比全表扫描代价更大时优化器会放弃，例如过滤出的行数占比过高（超过约 20% 左右）、索引区分度太低、回表次数太多，或对索引列使用函数导致无法定位。此时全表扫描加上顺序读反而效率更高，需结合统计信息判断。

473深挖

如何判断一条 SQL 是否发生了回表与回表次数，如何观察？

回表发生在所需列不在所用索引中时。可从 EXPLAIN 的 Extra 字段是否出现覆盖索引标记来侧面判断；回表次数与命中行数相关。用覆盖索引覆盖全部查询列，即可从根上避免回表。

474深挖

高并发下如果发现大量活跃事务与 undo log 无法清理，可能是什么原因？

常见原因是长事务或长连接未提交，其 ReadView 使旧 undo 版本链一直无法被 purge 清理，导致 undo tablespace 膨胀影响性能。可查 information_schema 的长事务，尽早提交或 kill 掉长期不提交的事务。

475深挖

一条 update 落到磁盘前经历了哪些缓冲与日志的时序（组提交）？

流程：更新 Buffer Pool 中对应页并写 undo；写 redo log 处于 prepare；写 binlog（多事务组提交 grouping commit 合并 fsync）；提交并把 redo 置 commit，再按刷盘策略把脏页最终落盘。

线程池只在核心线程数满且队列满后才新建非核心线程吗？核心数如何设？

477进阶

缓存穿透如何用布隆过滤器落地，误判会带来什么问题？

用布隆过滤器在查库前拦截不存在的 key，可有效防穿透但存在误判即可能误杀。误判会拦截少量合法请求应设置可容忍的误判率并配合缓存空值。布隆只增不删，适合固定冷热集合，删除类数据需重建或改用计数过滤器，权衡内存与准确。

478深挖

线上 Java 服务突然 CPU 飙高到 100%，你会如何一步步排查定位？请给出具体命令与思路。

479深挖

线上频繁 Full GC，你会如何用 jstat 与 jmap 定位并给出处置方案？

480深挖

线上出现 OOM，你的排查思路与对应命令是什么？

481深挖

一个对象从 new 出来到被 GC 回收，完整旅程是怎样的？

对象先分配在 Eden，经一次 Minor GC 若存活进入 Survivor，并标记 age 加一，age 达到 MaxTenuringThreshold 或晋级阈值满足后进入 Old。此后在 Old 的 Major/Full GC 中经可达性分析确认不可达，加入 finalize 相关处理，最终被标记清除。回收算法由 CMS、G1 等决定。

高并发下单次扣减库存如何做到安全且不过度扣？

网关流量突增，你如何设计限流与熔断降级？

接口如何保证幂等，尤其在支付、下单等场景？

客户端生成唯一 requestId，服务端用 Redis SETNX 或数据库唯一约束做幂等键，首次写入成功、重复请求直接返回旧结果。状态机加版本号避免重复改单，重试机制配合幂等键消费。核心是唯一键写库成功前不释放，防止并发重复提交。

缓存与数据库一致性如何保证？Cache Aside 与延迟双删的区别与适用场景？

Cache Aside 先更库再删缓存，存在并发窗口读旧数据；延迟双删在删缓存后延时再次删除，降低概率但不能彻底解决。若要求强一致可走 binlog 订阅（Canal）同步刷新缓存，或用顺序写保证。业务上多数接受最终一致，缓存设置过期兜底。

486深挖

延迟双删为何不彻底一致，若要用 binlog 订阅方案如何落地？

延迟双删的延迟是经验值，读旧写新并发窗口内仍可能读到脏数据，只是缩小概率。binlog 订阅用 Canal 监听 MySQL binlog，解析变更后异步刷新 Redis 并加版本号校验，避免旧值覆盖新值。因依赖消息异步，本质仍是最终一致而非强一致。

Redis SETNX、Redisson 与 ZooKeeper 分布式锁如何选型并对比？

Redisson 分布式锁为何能自动续期，Redis 主从切换时会丢锁吗？

缓存击穿、穿透与雪崩分别是什么，如何防护？

ThreadLocal 在线程池中使用为什么会内存泄漏，如何避免？

针对一个高并发读服务，JVM 参数你会如何设定并说明理由？

用 G1 或 CMS 视场景，-Xms 与 -Xmx 设为相等避免扩容抖动，堆大小结合对象量与 GC 目标；设置 -XX:MaxGCPauseMillis 与 UseG1GC，配合 -XX:+HeapDumpOnOutOfMemoryError 与 -XX:+PrintGCDetails。根据压测的 GC 频率与停顿调整新生代与分区，控制吞吐与延迟平衡。

一个接口响应慢，你如何通过多线程、数据库与缓存三者联合定位瓶颈？

先用 jstack 抓典型栈看线程阻塞与锁，再用日志分段统计耗时分布，定位 SQL 慢还是外部调用慢。SQL 用 EXPLAIN、缓存层看命中率 QPS，外部依赖看 RT 与超时。根据瓶颈分别优化索引、扩展缓存预热或并行化调用，最后压测验证改善。
