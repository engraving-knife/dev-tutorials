ClickHouse 投影操作

投影定义与物化命令

一条命令负责「定义投影」，一条命令负责「构建存量数据」——
两步配合，让投影在历史数据上真正生效。

🗂️ 两条命令总览

创建并启用一个投影，需要依次执行两条 ALTER TABLE 命令：

1
ADD PROJECTION —— 定义投影
声明投影的结构（名称、列、排序键），登记到表的元数据中。此后新写入的数据会自动同步进投影。
2
MATERIALIZE PROJECTION —— 物化投影
针对表中已存在的历史数据，真正构建投影的物理存储。存量数据不会自动物化，必须手动执行。

📝 命令一：ADD PROJECTION（定义投影）

SQL ALTER TABLE sales ADD PROJECTION sales_by_product ( SELECT * ORDER BY product_id );

语法结构

  • ALTER TABLE sales —— 指定要操作的表
  • ADD PROJECTION 投影名 —— 声明投影名称
  • SELECT ... ORDER BY ... —— 定义投影的数据组织方式（普通投影）
  • SELECT ... GROUP BY ... —— 定义聚合投影（预聚合）

作用：这一步只登记「投影方案」，不读取任何数据，执行速度很快。从此刻起，新写入的数据会自动按投影规则维护。

🔨 命令二：MATERIALIZE PROJECTION（物化投影）

SQL ALTER TABLE sales MATERIALIZE PROJECTION sales_by_product;

为什么需要这一步？

投影是「增量维护」的——ADD PROJECTION 之后的新数据会自动同步，但添加投影之前就已存在的历史数据不会自动重建，必须手动触发物化。

注意：默认是异步执行，大表可能耗时较长。可加 SYNC 关键字等待完成：ALTER TABLE sales MATERIALIZE PROJECTION sales_by_product SYNC;

🤔 为什么需要两条命令？

📋
ADD PROJECTION —— 注册投影定义（元数据，不读数据）
▼
🆕
新写入的数据 → 自动同步进投影（无需额外操作）
▼
🗄️
已存在的历史数据 → 不会自动物化，需手动执行 MATERIALIZE
▼
✅
MATERIALIZE PROJECTION —— 读取存量数据，按新排序键重建并写入投影存储
数据来源 是否自动物化 说明
添加投影之后新写入的数据 ✅ 自动 写入主表时同步更新投影，无需额外命令
添加投影之前已存在的数据 ❌ 需手动 必须执行 MATERIALIZE PROJECTION 构建

结论：如果表是空的，或不需要查询历史数据，可以只执行 ADD PROJECTION；否则两条命令都要执行。

🧰 常用配套命令

物化（同步等待）

SQL ALTER TABLE sales MATERIALIZE PROJECTION sales_by_product SYNC;

删除投影

SQL ALTER TABLE sales DROP PROJECTION sales_by_product;

查看投影是否命中（EXPLAIN）

SQL EXPLAIN SELECT * FROM sales WHERE product_id = 42;

输出中如果出现投影名称，说明查询已命中该投影。

提示：DROP PROJECTION 会同时删除对应的物理数据，操作前请确认不再需要。
